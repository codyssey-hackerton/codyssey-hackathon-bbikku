단계 1 이후의 증분은 PostgreSQL 저장 경계와 같은 DB의 pg-boss 예약을 중심으로 진행했다. 병렬 작업자는 실제 Terra·Google OAuth·음성/전화 제공자의 접근과 입출력을 확인한다. 연락 실행·상대 응답의 증거가 없으면 완료 상태로 넘기지 않는다.

## 단계 2 — PostgreSQL·시간 트리거

사용자의 후속 개발 요청에 따라 다음을 구현했다. 단계 1의 미연결 DB·예약 항목은 아래 상태로 갱신한다.

- PostgreSQL에 일정·Memory·제안·불변 승인·대화·멱등 결과·예약 설정·실행 기록을 저장한다. 사용자 행 잠금과 트랜잭션으로 상태 변경/응답을 함께 확정하고 모델 호출 중에는 DB 잠금을 유지하지 않는다. 결과 미수신 후 같은 키를 재전송하면 이미 확정한 결과를 돌려준다. 실행 도중 중단된 DB 작업은 lease 만료 후 새 소유권으로 복구하고 이전 실행자의 저장을 차단한다.
- 앱에서 자동 검토 설정을 저장한다. 저녁은 다음 날, 아침은 당일을 대상으로 하며 초기에는 모두 꺼짐이다. pg-boss가 서버에서 실행하고 같은 Agent의 읽기·제안 검증 경로를 사용한다. 자동 검토는 승인·일정 적용·연락 발송을 하지 않는다.
- 30초마다 DB 설정과 예약 큐를 대조한다. 이 대조는 LLM 호출이 아니다. DB의 설정 저장 시각 이후 발생한 60분 이내 누락 건만 회복하며, 새 설정 이전 시각을 소급 실행하지 않는다. 60분 초과·비활성·이전 설정 버전은 건너뛰고 그 근거를 기록한다. DST 반복 시각은 먼저 발생한 시각을 택하고 존재하지 않는 시각은 건너뛴다.
- 로컬 PostgreSQL은 `npm run dev:db`, API/앱/예약은 `npm run dev:local -- --postgres --scheduler`로 실행한다. DB 종료 후 파일은 보존한다. `PIKKU_DATABASE_URL`이 없는 일반 실행은 여전히 메모리 모드다.
- 실제 로컬 PostgreSQL에서 상태/승인/대화 복구, 다중 인스턴스 CAS, lease 재개·소유권 차단·COMMIT 응답 유실, 예약 제안/실행 기록의 중복 방지와 설정 변경 경합을 검사했다. 별도 실제 서버 프로세스의 재시작 후 저장·응답 재사용도 확인했다. 모델은 합성 테스트 모델이며 실제 Terra 품질/접근 검증이 아니다.

**저장 구조 인계:** `pikku_user_state_v1`은 사용자별 버전 있는 JSONB 문서인 일반 영속 테이블이다. PostgreSQL 임시/UNLOGGED 테이블이 아니다. 현재 엔진과 계약을 빠르게 유지하는 초기 repository 구현으로, 찬욱님의 정규화된 테이블 설계가 전달되면 데이터 보존 마이그레이션을 함께 맞춘다. 사용자 상태가 커지면 JSONB 전체 쓰기·행 잠금 비용이 증가하며, 예약 대조도 사용자 목록 전체를 읽으므로 대규모 운영 최적화는 미완료다. 기록 자동 삭제/보존정책과 운영 인증·호스팅도 후속이다.

**단계 2 초기 검증:** `npm run test:postgres` **259개 통과, 실패/skip 0개**(API 137 / 모바일 82 / 도메인 40). 전체 typecheck, iOS·Android export, 실제 PostgreSQL+Scheduler 서버의 인증된 기동/종료 검사 통과. 새 큐 등록은 기존 재시도 시각을 변경하지 않으며 결정적 작업 ID로 동시 등록을 막는다. 실제 PG에서 구버전 재시도 작업의 재시작 보존·조기 실행 차단과 두 scheduler의 동일 예약 한 건 등록도 확인했다. 예약→Agent/제안 검증은 합성 모델 기반이며 실제 Terra 호출/실기기/메일·전화 검증은 포함하지 않는다. 이 검증은 커밋 전 로컬 스냅샷에서 수행했으며 운영 배포는 하지 않았다.

**단계 2 초기 제공자 상태:** 당시 프로젝트 AI 키가 없어 검증 CLI는 `not_configured`, 실제 요청 0건이었다. [모델 검증](MODEL_VERIFICATION.md)의 정확한 모델/추론 강도 검사 명령을 준비했다. [외부 API 준비](PROVIDER_SETUP.md)는 공식 문서 검토 결과이며 인증된 연결·메일 발송·전화 성공 증거가 아니다. 필요한 키는 `.env.local` 또는 서버 비밀 설정에만 둔다. 다음 구현은 실제 키 접근 확인, 연락 승인·상대 응답·캘린더/Gmail/전화 연결이다.

## 실제 AI·Gmail 증분 — 2026-10-31

- Responses 함수 호출의 원본 output과 같은 `call_id`의 결과를 이어 보내도록 수정했다. 실제 `verify:model`은 HTTP 2회로 통과했다.
- **실제 PostgreSQL + HTTP + Terra/high + pg-boss 검증 8항목 통과.** 합성 일정의 직접 추천과 실제 예약 추천 각각 승인 전 일정 유지, 승인 한 번 반영, API/DB 연결 재생성 후 복구를 확인했다. 모델 요청은 총 8회이며 중복 예약 재전달에는 추가 호출이 없었다. 세부 범위·증거는 [모델 검증](MODEL_VERIFICATION.md)에 기록했다.
- 연락 초안 증분 당시 `npm run test:postgres` **314개 통과, 실패·skip 0개**(API 189 / 모바일 85 / 도메인 40). 전체 typecheck와 실제 검증 스크립트의 별도 typecheck, `git diff --check` 통과. 이번 서버 증분에서는 모바일 번들 재생성·실기기 재검증을 하지 않았다.
- 별도 개발 API `127.0.0.1:3002`는 PostgreSQL 저장과 Scheduler를 켜고 인증된 capabilities 응답을 확인했다. 기존 `3001` 메모리 서버는 보존했다. 이후 Gmail UI 증분에서 iPhone 시뮬레이터 앱을 `3002`와 해당 세션으로 전환하고 인증된 제안 조회를 확인했다. 앱에서 PostgreSQL을 쓰려면 개발 연결 주소를 `http://127.0.0.1:3002`(Android 에뮬레이터 `http://10.0.2.2:3002`)와 해당 `.local/dev-session-3002.txt` 토큰으로 바꾼다. 기존 메모리 일정의 자동 이관은 하지 않았다.
- 새 서버는 기존 PostgreSQL 행을 읽을 수 있다. 연락 기능을 사용하지 않은 행에는 빈 새 필드를 쓰지 않는다. 연락 데이터가 저장된 행은 이전 버전의 strict decoder가 읽지 못하므로 같은 DB에 구버전 서버를 혼합 실행하거나 그대로 롤백하면 안 된다. 운영 배포는 하지 않았다.
- 사용자 결정에 따라 Gmail부터 진행한다. 수신자 등록·연락 초안·조회·승인 API와 불변 스냅샷/멱등 결과의 PostgreSQL 저장을 구현했다. 승인해도 `ready`까지만 전환하고 원래 공동 일정은 유지한다.
- 독립 검수에서 만료된 연락 요청을 거절할 수 없는 결함을 수정했다. reject는 원본 초안·소유자·버전·대기 상태를 지키며 종료하고, accept에만 현재 수신자·일정·맥락·대안 유효성을 재검증한다. 변경 후 실제 PG 재연결·재전송 검사까지 통과했다.
- Gmail 어댑터는 한글 MIME·헤더 입력 검증·제공자 결과 분류·자동 재발송 금지를 모의 검증했다. 이 시점에는 OAuth·발송 실행기·연락 UI가 미구현이었다. 아래 후속 증분에서 연결했으며 실제 전송·회신·상대 수락 반영은 여전히 별도 검증 대상이다. 외부 메일·전화는 실행하지 않았다.
- 다음 순서: Google OAuth와 발신 계정 연결 → 승인된 내용의 실행 의도 저장/단일 발송 → 테스트 수신 확인 → 회신과 상대 수락·일정 재검증. [제공자 준비](PROVIDER_SETUP.md)에 필요한 설정과 경계를 기록했다.

## Gmail 발송·연락 UI 연결 증분

- 공동 조정 제안에서 편집 가능한 정형 메일 초안과 수신자 확인, 불변 승인 미리보기, 별도 Gmail 발송 버튼을 연결했다. 초안에는 일정 제목·허용 시간만 쓰며 개인 맥락이나 제안 이유를 자동 공유하지 않는다. 기존 연락 목록을 다시 읽어 화면 재진입을 복구한다.
- 로컬 개발용 웹 OAuth CLI `npm run connect:gmail`와 토큰 갱신·검증된 계정 바인딩을 구현했다. 실제 계정 인증은 사용자 Google Cloud 설정·동의 후 확인한다. 운영 다중 사용자 OAuth를 구현한 것은 아니다.
- PostgreSQL에 실행 의도·중복키를 먼저 기록하고 DB 잠금 밖에서 Gmail을 단일 시도한다. UI가 확인한 발신 주소를 요청/멱등 지문에 묶어 계정이 바뀌면 발송을 거절한다.
- OAuth를 기다리는 동안 일정이 바뀌지 않았는지 Gmail 요청 직전에 재검증한다. 최초 claim의 절대 기한과 취소 신호를 유지해 서버 지연 뒤 새 발송이 시작되지 않게 한다. 최종 DB 검증과 외부 네트워크 실행을 완전한 원자적 작업으로 보장하지는 않는다.
- 결과 불명은 자동 재발송하지 않는다. 계정 연결이 해제돼도 기존 요청의 저장 결과부터 복구한다. 발송 전 충돌과 발송 후 결과 불명을 오류 코드로 구분해 UI가 처리한다.
- 최종 통합 `npm run test:postgres`: **387개 통과, 실패·skip 0개**(API 223 / 모바일 124 / 도메인 40). 전체 typecheck, iOS·Android export, `git diff --check` 통과. 실제 PG·localhost HTTP·모바일 연락 client·Gmail MIME adapter를 연결한 테스트는 발송 fetch만 모의이며 실제 메일이 아니다. iPhone 시뮬레이터에서는 PostgreSQL 개발 연결과 제안 조회를 확인했고 연락 전체 흐름의 실기기 조작은 수행하지 않았다. 스테이징 검사에서는 Pretendard 라이선스 원문의 공백 1건을 확인해 원문 보존 예외로 두었고 나머지 파일 검사는 통과했다.
- 실제 Google 계정 동의·Gmail 발송은 자격증명 준비 전 미검증이다. 전화와 회신 읽기·상대 수락·최종 일정 반영은 이번 증분에서 구현하지 않는다.

## 필수 검수 시나리오

1. 고정 약속과 유동 작업을 직접 등록하고 같은 ID/버전을 월별·하루 화면에서 확인한다. 저장 충돌은 다른 일정을 자동 이동하지 않는다.
2. 단순 인사는 답변만. 추천 요청은 필요한 Tool·질문을 사용하며 변경 초안은 코드 검증 후에만 승인 가능한 제안이 된다.
3. 승인 전/거절 후 일정 유지. 개인 승인 후 선택한 변경만 반영. 동일 승인/키 재전송은 같은 결과, 같은 키 다른 본문은 충돌.
4. 제안 생성 중/승인 직전 일정 또는 Memory 변경은 오래된 적용 차단. 제안/일정/대화는 사용자 범위를 넘지 않는다.
5. 고정·완료 항목 보호, task 소요시간/마감/겹침 검증. 공동 약속 조정은 선택 범위의 검토만 허용하고 상대 수락 전 변경하지 않는다.
6. 모델·DB·외부 API 미설정/오류/불명과 실제 빈 데이터를 구분한다. 부작용 결과 불명 상태를 무조건 재실행하지 않는다.
7. 모바일 연결 변경 시 이전 사용자의 대화/일정/제안/늦게 도착한 응답을 버린다. 키·토큰은 로그·Git에 포함하지 않는다.

검증 근거는 단위/HTTP 통합/모바일 번들/실기기/실제 제공자 호출로 구별한다. 테스트 모델이 있는 통합 검증만으로 실제 AI 품질과 외부 연동 완료를 주장하지 않는다.

## 의존성 검사 메모

통합 설치의 npm audit는 Expo CLI 경로를 포함해 13개 항목(높음 3개)을 보고했다. 높은 등급의 직접 원인은 Expo CLI의 Zod 3 계열이며 API가 쓰는 Zod 4.6.7과 구분된다. 자동 수정안이 Expo 58에서 54로 변경하므로 강제 적용하지 않았다. SDK 호환 수정 버전은 배포 전 재검토한다. 이 수치는 당시 검사 결과이며 실제 악용 확인을 뜻하지 않는다.

런처는 기본 루프백이며 `--lan`은 명시적 개발 옵션이다. LAN HTTP의 토큰/데이터는 암호화되지 않고 Expo Metro의 개발 엔드포인트에는 앱 API 인증이 적용되지 않는다. 이를 운영 인증으로 간주하지 않으며 신뢰 가능한 사설 네트워크·합성 데이터에만 사용한다. 외부 시연 배포 전 HTTPS·실제 인증·개발 서버 제외가 필요하다. LAN 원격 침투 검사는 하지 않았다.
