# 디자인 결합용 기능 연결표

2026-11-01. 현재 구현과 디자인의 연결 및 검증 경계다. 최신 증분은 바로 아래에 기록하고, 이후의 이전 계획과 검증 기록은 당시 상태로 보존한다. 임의로 디자인 화면을 추정해 추가하지 않는다.

## 초안 진입·제안 표시 보완 — 최신 증분

- 처리 중이거나 결과가 불명인 요청이 있어도 추가 화면에 들어가 초안을 작성할 수 있으며, 새 저장은 기존 요청 확인 전까지 차단한다.
- 제안 화면에서 내부 식별자·버전·생성 시각·검증 메타데이터를 숨기고, 전후 변경·판단에 필요한 필드·승인 경고는 유지한다.
- 기존 사용자 탭의 미확정 요청 보존을 위해 새로고침과 재시작을 하지 않았다. 실제 채팅 ledger 진단은 running 0건·retryable 1건이며 제공자 실패의 정확한 원인은 확인되지 않았다.
- 모델 호출 제한은 호출별 60초, Agent 최대 10단계, 클라이언트 180초다. 서버 전체 처리시간 제한과 독립 상태 조회는 구현되지 않았다.
- Gmail 발송·회신 통합 동의는 조사와 추천 단계이며 구현하지 않았다. 수정 요청 초안의 내부 ID·JSON은 별도 API context 부재로 현행을 유지하고, 긴 텍스트 8천 자 제한은 후속 과제다.

## 로그인·온보딩·프로필 통합 — 최신 증분

- **디자인 근거:** 00의 공식 Figma 도구 확인에서 메인 화면 일부(`2:862`, `28:852`)와 서브 파일의 온보딩 페이지(`97:2`) 접근에 성공했다. 카드 59개 인스턴스 전체를 직접 확인한 것은 아니다. 서브 디자인은 흐름 참고이며 기존 Pretendard·색상·캐릭터·공통 컴포넌트를 유지한다.
- **흐름과 저장:** Welcome, 실제 Google 회원 인증 경로, 3단계 선호 입력과 프로필을 연결했다. 선호는 기존 Memory의 사용자별 `planning_preferences` v1 preference로 저장한다. Agent 프롬프트는 사용자 출처의 선택값만 참고하도록 지시하며, 공통 Memory API는 일반 JSON을 받아 형식이나 모델 행동을 결정적으로 보장하지 않는다. 선호 조회·저장은 일정 자동 변경이 아니다. 상세 값과 리비전 경계는 [CONTRACTS](CONTRACTS.md)를 따른다.
- **검증:** 00이 전달한 최신 결과는 모바일 전체 **384개**, workspace typecheck, 최종 avatar 집중 **51개**, web export 통과다. Calendar 읽기 fallback 관련 합성 검사는 **18개** 통과했다. 이 집계는 서로 다른 검사 범위이므로 합산하지 않는다.
- **실제 제공자 확인:** 00이 기존 개발 계정의 연결 상태 4개와 실제 Calendar 목록 3개 조회를 확인했다. 이는 새 회원 로그인 성공이나 일정 쓰기 검증이 아니다.
- **로컬 실행:** `19006` 웹의 기본 API는 실제 회원 인증·영속 프로젝트 PostgreSQL을 사용하는 `19012`다. 기존 개발 연결 `19011`은 보존하고 합성 QA API `19009`는 별도다. 포트와 연결 상태는 확인 시점의 로컬 환경 기록이며 배포 주소가 아니다.
- **웹 회원 로그인 확인:** 실제 회원 로그인·온보딩 진입·Memory 조회를 확인했다. 읽기 전용 PostgreSQL 집계에서 회원과 유효 세션의 영속성 및 개발 계정과의 분리를 확인했다. 최초 OAuth의 `redirect_uri_mismatch` 원인은 확정되지 않았다.
- **남은 범위:** 신규 회원의 Calendar·Gmail은 각각 별도 권한 동의가 필요하다. 이번 증분의 iPhone·실제 전화 검증은 보류다. PR #17은 Draft로 미병합이며 이번 작업의 커밋·푸시·배포는 하지 않았다.

## 결합 원칙

- 기존 API client·hooks·mutation/operation guard와 화면 로직을 재사용하고 표시 부분을 교체한다. UI 안에 있는 상태 로직까지 지우거나 모든 로직이 이미 hook으로 분리됐다고 가정하지 않는다.
- 서버가 주는 제안 ID/버전·상태·충돌을 그대로 연결한다. 버튼 색이나 화면 전환만으로 저장/승인 성공을 표시하지 않는다.
- 진행 중·결과 불명 요청을 버리고 계정을 바꾸지 않는다. Calendar 실행 응답 유실은 같은 요청의 저장 결과 GET으로 확인하고 외부 쓰기를 다시 보내지 않는다.
- Pretendard, 기존 `Text`/`TextInput`, `ActionButton`, `GlassSurface`, `Icon`과 테마를 우선 사용한다. 새 Figma 자산/색·레이아웃은 실제 파일을 확인한 뒤 적용한다.
- 루틴 회차는 수동 생성 범위 최대31일이며 할 일/루틴 회차의 Google 내보내기는 현재 지원하지 않는다. 공유 일정의 원본 시간 반영은 이미 적용된 연락 합의와 정확한 원본·권한 증거가 있을 때만 허용한다.
- 통화 전용 프롬프트는 팀원 브랜치 검수 후 현재 디자인 브랜치에 병합했다. ClawOps에 저장된 Agent 반영과 실제 통화 검증은 별도다.

## 디자인 결합 전 기능 보완 — 이전 증분

- 로그인 화면에서 건강 화면으로 전환할 때 인증 화면이 계속 남는 문제를 수정하고 진행 중 인증은 보호한다.
- 루틴 재진입 시 바뀐 선택 날짜를 미수정 기본 날짜에 반영하며 작성 중 초안과 미확정 작업은 유지한다.
- 기존 Calendar 연결에 새 개인 이벤트를 추가 선택해 내보낼 대기열에 넣는 경로를 제공한다. 기존 매핑과 멱등 기록을 보존한다.
- 실제 PostgreSQL/HTTP 종단에서 발견한 Calendar 실행의 중첩 트랜잭션 자기 잠금을 제거한다. 실행은 자체 영속 ledger로 보호하며 불명 외부 작업을 자동 재실행하지 않는다.
- 연락 합의 적용 후 Google 원본 시간 업데이트는 사용자 승인·확인된 응답·정확한 현 일정·원본 etag·Calendar owner와 주최 계정 일치를 재검증한다. 타인 주최·공유 캘린더 writer·미확인/변경된 증거는 계속 차단한다.

이전 증분의 앱 UI에서 Google Calendar `calendar.events` 쓰기 추가 동의·콜백·코드 입력과 연결 완료를 확인했다. 별도 비공개 자격 경로와 격리 메모리 환경의 `local-developer`로 실제 토큰 갱신과 캘린더 목록 3개(쓰기 가능 2개)를 조회했으며 실제 일정 쓰기는 0건이다. 실회원 로그인·운영 계정 이관·PostgreSQL 종단 검증은 아니다. 별도 설치한 당시 iPhone 개발 빌드에서 실제 화면 표시, 달력 날짜 선택·유지와 채팅 입력·삭제를 확인했으며 발송은 하지 않았다. 당시 실기기 Google 로그인·AI·실서버 통신, 소프트 키보드 높이·건강 권한과 Figma 화면 결합은 미검증이었다.

당시 API 전체501/501(skip0)·workspace typecheck·검증용 web export 통과. 모바일 전체318/318과 최종 문구의 앱 통합31/31은 별도 검사 기록이다. 당시 PostgreSQL/HTTP 종단은 기존 컴포넌트를 stub한 화면 테스트와 달리 실제 API·회원 세션·루틴/일정/체크인·선택 내보내기·사용자 분리·로그아웃까지 연결하고 외부 Google만 모의 포트로 대체했다.

## PR #17 디자인 통합 진행안 — 이전 계획

- 시각·조작 기준은 PR #17의 HTML과 자산(`docs/pikku-design-handoff`, 확인 커밋 `3750846`)이며 최신 PRD·ADR·CONTRACTS의 실제 기능과 연결한다. Draft PR은 참고용으로 조회하며 병합하지 않는다.
- 작업 Figma 복제본은 `b5uT3NqN5Y45uw74V8GH0L`이다. 당시 사용자 전달에 따르면 카드 59개와 카드 내부 상태 버튼은 공통 인스턴스에 연결됐고 기존 상태·더보기 터치 영역도 옮겨졌다. 일반 행동 버튼은 기존 레이어다. 당시 공식 도구 접근이 실패해 이 전체 상태는 직접 검증하지 못했다. 이후 확인 범위는 최신 증분을 따른다.
- 목록 카드와 일간 타임라인 카드의 시간 배치를 구분한다. Pretendard·프로필·캐릭터는 HTML 표현을 따르고 Streamline 자산과 출처 표기를 유지한다. 목업의 예시 AI·브라우저 저장을 실제 연결로 옮기지 않는다.

선행 보완 제안(아직 채택·구현된 계약 아님):

- 수행과 참석: 현재 completion은 종류 공통이고 별도 참석 기록이 없다. event의 참석 기록을 task·루틴 수행 기록과 분리하고, 기존 값의 호환 및 AI의 완료 보호·공동 조정 조건을 함께 검토한다.
- 완료 취소: checkin은 pending 복귀를 받지 않고 이전 기록도 보존하지 않는다. HTML처럼 직전 미완료/미기록 상태를 복원하려면 서버에 직전 상태 한 단계를 보존하고 revision·멱등 처리와 함께 원자적으로 복원한다. unknown을 미기록으로 바꾸어 해석하거나 화면 메모리만으로 기기 간 복원을 보장하지 않는다.
- 개인/업무: personal/shared 참여 범위와 다른 정보다. 최소안은 일정·루틴의 선택적 category(personal/work/null), 기존 데이터는 미분류(null), 회차는 생성 시 규칙의 category를 보존하는 것이다. 기존 회차는 임의 재분류하지 않는다. 계약 반영 전에는 전체만 실제 연결하며 개인/업무를 추정하지 않는다. 별도 tags 설계는 추가하지 않는다.
- AI 맥락: 범용 항목·폼 초안 context 및 AI 반복 규칙 변경의 승인 실행 계약이 현재 없다. 필요한 범위만 정의하며 루틴 일괄 수정·자동 회차 생성 등은 기존 구현으로 표시하지 않는다.

공통 인터페이스 정리 후 01 공통 UI, 02 도메인/API, 03 홈·캘린더, 04 루틴·추가, 05 AI 화면으로 수정 파일을 분리하는 안이다. 00은 App shell·공통 계약 검수와 통합, 06은 Git 격리·최종 검증을 맡는다. 공통 카드와 중앙 라우터는 단일 소유자가 수정하며 공유 변경은 합의 후 반영한다.

위는 구현 전 작성한 계획이다. 이후 사용자가 추천 순서대로 실제 병렬 구현을 요청했으며 현재 결과는 다음 절에 기록한다. Google 로그인·실모델 기기 검증의 보류 상태는 유지한다.
