# 디자인 결합용 기능 연결표

2026-11-01. 현재 구현을 새 Figma 화면에 붙일 때 보존할 연결이다. **팀 Figma 링크는 아직 전달 전이므로 화면/버튼 전수 대조와 시각적 일치는 미확인**이다. 임의로 디자인 화면을 추정해 추가하지 않는다.

| 사용자 동작 | 기존 구현/연결 지점 | 디자인에 필요한 상태 |
|---|---|---|
| 가입·로그인·로그아웃 | `src/auth`, `App.tsx`, `/v1/auth/*` | 외부 동의/확인 코드, 처리 중, 결과 불명, 만료, 계정 전환 제한 |
| AI 대화·추천·추가 질문 | `src/chat`, `/v1/chat` | 답변/질문/제안, 로딩, 실패, 같은 요청 재시도, 메모리/상황 진입 |
| 월간·하루·직접 일정 | `src/screens`, `src/schedule` | 날짜 선택, 빈 목록/오류, 개인/공동·고정/유동, 완료/미완료/미확인 |
| 선호·일시 상황 | `src/memory` | 저장/수정/삭제, 출처·유효기간, 충돌/만료/불명 결과 |
| AI 변경 승인 | `src/proposals` | 변경 전후, 승인/거절/수정, 오래됨/만료, 공동 약속 연락 대기, 반영 완료 |
| 이메일·전화 연락 | `src/contacts` | 대상/내용/대안 확인, 연락 승인과 실행 분리, 발송/대기/실패, 회신 검토/최종 확인 |
| 전날·아침 자동 검토 | `src/review`, 기존 서버 Scheduler | 초기 꺼짐, 시각/시간대, 저장/실패, 설정과 제안 승인 구분 |
| Calendar 읽기·선택 가져오기 | `src/google`, `src/calendar` | 권한별 연결/실패/재동의, 원본 선택, 중복/지원 불가 |
| 반복 루틴·회차 | `src/routines` | 요일/시각/기간, 수정·비활성, 생성 충돌, 기존 회차 유지, 하루로 이동 |
| Calendar 원본 동기화 | `src/calendar-sync` | 쓰기 별도 동의, 신규 연결/기존 연결 추가 선택, 실행, 삭제 동의, 충돌/검토 필요/저장 결과 재조회 |

| 선택적 건강 연결 | `src/health` | 항목별 선택/OS 읽기 동의, 미지원/빈값·부분값, 연결해제. 실제 기기 검증은 보류 |

위 `src/` 경로는 `apps/mobile/src/` 기준이다. HTTP 필드와 오류는 [CONTRACTS](CONTRACTS.md), 회원/루틴/동기화의 제한은 [사용 안내](MEMBER_ROUTINE_CALENDAR.md)를 따른다.

## 결합 원칙

- 기존 API client·hooks·mutation/operation guard와 화면 로직을 재사용하고 표시 부분을 교체한다. UI 안에 있는 상태 로직까지 지우거나 모든 로직이 이미 hook으로 분리됐다고 가정하지 않는다.
- 서버가 주는 제안 ID/버전·상태·충돌을 그대로 연결한다. 버튼 색이나 화면 전환만으로 저장/승인 성공을 표시하지 않는다.
- 진행 중·결과 불명 요청을 버리고 계정을 바꾸지 않는다. Calendar 실행 응답 유실은 같은 요청의 저장 결과 GET으로 확인하고 외부 쓰기를 다시 보내지 않는다.
- Pretendard, 기존 `Text`/`TextInput`, `ActionButton`, `GlassSurface`, `Icon`과 테마를 우선 사용한다. 새 Figma 자산/색·레이아웃은 실제 파일을 확인한 뒤 적용한다.
- 루틴 회차는 수동 생성 범위 최대31일이며 할 일/루틴 회차의 Google 내보내기는 현재 지원하지 않는다. 공유 일정의 원본 시간 반영은 이미 적용된 연락 합의와 정확한 원본·권한 증거가 있을 때만 허용한다.
- 통화 전용 프롬프트는 별도 팀원 브랜치에서 작업 중이다. 그 결과를 현재 기능 코드에 자동 덮어쓰거나 main 병합 완료로 취급하지 않는다.

## 이번 기능 보완

- 로그인 화면에서 건강 화면으로 전환할 때 인증 화면이 계속 남는 문제를 수정하고 진행 중 인증은 보호한다.
- 루틴 재진입 시 바뀐 선택 날짜를 미수정 기본 날짜에 반영하며 작성 중 초안과 미확정 작업은 유지한다.
- 기존 Calendar 연결에 새 개인 이벤트를 추가 선택해 내보낼 대기열에 넣는 경로를 제공한다. 기존 매핑과 멱등 기록을 보존한다.
- 실제 PostgreSQL/HTTP 종단에서 발견한 Calendar 실행의 중첩 트랜잭션 자기 잠금을 제거한다. 실행은 자체 영속 ledger로 보호하며 불명 외부 작업을 자동 재실행하지 않는다.
- 연락 합의 적용 후 Google 원본 시간 업데이트는 사용자 승인·확인된 응답·정확한 현 일정·원본 etag·Calendar owner와 주최 계정 일치를 재검증한다. 타인 주최·공유 캘린더 writer·미확인/변경된 증거는 계속 차단한다.

최신 앱 UI에서 Google Calendar `calendar.events` 쓰기 추가 동의·콜백·코드 입력과 연결 완료를 확인했다. 별도 비공개 자격 경로와 격리 메모리 환경의 `local-developer`로 실제 토큰 갱신과 캘린더 목록 3개(쓰기 가능 2개)를 조회했으며 실제 일정 쓰기는 0건이다. 실회원 로그인·운영 계정 이관·PostgreSQL 종단 검증은 아니다. 기기용 Debug 서명 빌드·설치는 성공했고 실제 화면과 Figma 결합 검증은 대기 중이다.

최종 API 전체501/501(skip0)·workspace typecheck·검증용 web export 통과. 모바일 전체318/318과 최종 문구의 앱 통합31/31은 별도 검사 기록이다. 새 PostgreSQL/HTTP 종단은 기존 컴포넌트를 stub한 화면 테스트와 달리 실제 API·회원 세션·루틴/일정/체크인·선택 내보내기·사용자 분리·로그아웃까지 연결하고 외부 Google만 모의 포트로 대체한다.
