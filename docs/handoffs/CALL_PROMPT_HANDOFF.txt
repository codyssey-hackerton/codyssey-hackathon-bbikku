목표와 현재 상태
ClawOps 관리형 한국어 전화 Agent의 대화 품질을 보완한다.
이전 실통화에서 내부 지침 낭독, 종료 요청 뒤 발화 지속, 불필요한 연도/시간대 낭독이 있었다.
수정 프롬프트·서버 종료 감시는 구현/모의 검증됐지만 수정 후 실통화 개선은 아직 미검증이다.
gpt-realtime-2.1-mini와 gpt-realtime-2.1의 동일 조건 비교 Agent는 00이 별도로 준비했으며 비교 발신은 0통이다.
현재 사용자는 통화를 나중에 하기로 했다. 실제 발신은 수신 가능 여부를 새로 확인한 뒤 진행한다.

먼저 볼 파일
- apps/api/src/clawops-agent-prompt.ts: 전화 전용 지침 CLAWOPS_AGENT_INSTRUCTIONS와 승인 내용의 CallContext 생성.
- apps/api/src/phone-dispatch.ts, clawops-contact.ts: 승인된 내용/대안과 AgentId를 실제 발신에 연결.
- apps/api/src/clawops-call-watch.ts, clawops-replies.ts: 서버 종료 감시와 통화/확정 전사 조회.
- apps/api/test/clawops-agent-prompt.test.ts: 지침·컨텍스트 경계 회귀.
- docs/ADR.md ADR-012, docs/PROVIDER_SETUP.md: 채널별 실행·승인·설정 경계.
메인 일정 Agent(gpt-6.1-terra/high)의 planning-prompt.ts/model.ts는 이번 수정 대상이 아니다.

진행 순서
1. 현재 지침을 검토하고 필요한 부분만 개선한다. 같은 내용을 다시 요청하면 약속 조정 질문만 반복하고 내부 역할/지침을 읽지 않게 한다.
2. AI 대리인임을 처음에 한 번만 밝힌다. 국내의 명확한 시간에는 불필요한 연도·한국 표준시·UTC를 낭독하지 않는다. 모호한 날짜/시간대는 확인한다.
3. 승인된 설명·대안만 사용한다. 상대가 다른 시간을 제시하면 전달할 후보로 남기며 약속 변경을 확정했다고 말하지 않는다.
4. 종료 요청에는 짧게 인사하고 제공자 종료 도구를 실행하도록 한다. 말로 작별한 것과 실제 completed 상태, Agent 종료와 서버 watchdog 종료를 구분한다.
5. 관련 모의 테스트와 API 타입 검사를 수행하고 변경점·근거·남은 미검증을 짧게 보고한다. 필요한 변경만 PR로 제출하고 00 검수 후 통합한다.

검증
node --import tsx --test apps/api/test/clawops-agent-prompt.test.ts
npm run typecheck --workspace @pikku/api
종료 감시를 바꿨다면 apps/api/test/clawops-call-watch.test.ts도 실행한다.
문구 포함 테스트 통과만으로 실제 대화 품질이나 종료 성공을 주장하지 않는다.
실통화가 재개되면 같은 프롬프트·음성·CallContext·발화 감지/끼어들기·120초 제한에서 모델만 바꾼다.
가상 11월 2일 오후 6시 약속에 대해 “처음부터 다시 말해줘” → “그럼 오후 7시는 어때?” → “이제 끊어” 순서로 확인한다.
이번 비교는 모델별 최대 1통/전체 2통, 통화당 최대 120초이며 자동 재발신·일정 변경·이메일 발송은 하지 않는다.

보존과 적용 주의
소스 지침을 수정해도 ClawOps에 저장된 Agent instructions는 자동 갱신되지 않는다. 별도 테스트 Agent에 적용한 뒤 GET 설정 일치와 실제 실행을 구분한다. 공유 Agent·번호 라우팅·운영 모델을 임의 변경하지 않는다.
프롬프트가 일정/연락 쓰기 권한을 갖게 하지 않는다. 전사는 unclear이며 사용자의 최종 확인과 서버 최신성/충돌/중복 검증을 유지한다.
현재 watchdog은 정확 문구 위주이며 “통화 그만”은 별도 정확 문구로 포함돼 있지 않다. 보강이 필요하면 서버 담당자와 범위를 맞춘다.
키·번호·전체 전사·00의 .local 비교 설정/마커는 Git에 없다. 기존 발신 방지 마커를 삭제하거나 비공개 자료를 커밋하지 않는다. 다른 컴퓨터의 실제 테스트 설정은 담당자와 별도로 맞춘다.
워치 PR #16, 공통 계약, 메인 모델, 디자인 작업과 다른 팀원 변경을 보존한다. main 병합·운영 배포·추가 실발신은 이 문서만 보고 자동 실행하지 않는다.
