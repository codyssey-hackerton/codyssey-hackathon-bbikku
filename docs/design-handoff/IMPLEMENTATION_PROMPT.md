## 자료 확인
저장소 AGENTS.md와 최신 docs/PRD.md, MEETING_ALIGNMENT.md, ARCHITECTURE.md, ADR.md, CONTRACTS.md를 먼저 읽으세요.
docs/design-handoff/README.md와 developer-handoff.md를 읽고, probes/reference-wireframe.html 및 assets의 CSS·JS·폰트·이미지를 확인하세요.
probes/final-preview.html은 화면별 구성, design-rules.md는 디자인 규칙, feedback-original.md는 사용자 요구 원문입니다.

## 적용 원칙
확정된 시각 스타일과 조작 방식은 HTML 목업, 화면 구성과 공통 부품은 Figma도 함께 참고하세요.
Figma 02 Components에 공통 카드·버튼 원본은 있지만 기존 화면 전체에 적용되지는 않았습니다.
모달·상태 예시를 별도 페이지로 만들지 마세요. 기존 앱의 구조·API·인증·상태 관리·공통 부품을 재사용하세요.
목업 코드를 통째로 앱에 삽입하거나 가상 AI 응답과 브라우저 저장을 운영 구현으로 간주하지 마세요.
공통 계약 변경은 저장소 담당자 확인 규칙을 따르고, 자료 간 중요한 충돌은 구체적으로 알려 주세요.

## 시각 디자인
아이폰·안드로이드 공통으로 연한 블루·라일락 배경, 둥근 화이트 카드, 일정 색상 구분선, 부드러운 그림자와 Pretendard를 유지하세요.
홈 / 캘린더 / 중앙 AI 비서 / 추가 / 루틴 내비게이션, 기존 삐꾸 캐릭터와 프로필 표현을 유지하세요.
Figma의 임시 폰트·프로필을 최종 디자인으로 쓰지 마세요. 전달된 아이콘과 라이선스를 유지하세요.

## 상태와 카드
할 일·루틴의 완료·미완료·미확인, 약속·회의의 참석·불참·미확인을 구분하세요.
아무 기록이 없거나 시간이 지났다는 이유로 실패·완료·불참 처리하지 마세요.
시간상 진행 중과 실제 수행 기록을 분리하세요. 완료 취소와 홈·일간·루틴의 기록 공유를 구현하세요.
루틴의 날짜별 수행 기록과 전체 반복 규칙을 분리하세요. 완료율은 실제 완료 확인된 할 일·루틴 기준입니다.
오른쪽에는 짧은 상태 버튼과 세로 더보기를 두세요. 완료 버튼은 내용에 맞는 표시 폭과 최소 44×44 터치 영역을 갖추세요.
루틴 완료됨은 체크 아이콘 없이 색과 글자로 표시하고, 중복 상태 문구는 피하세요.
상세·수정·삭제·상태 변경·AI 요청은 유형과 상태에 맞는 바텀시트로 제공하세요.

## 카드 스택과 달력
현재 또는 다음 일정이 전면에 오고, 종료한 일정은 실제 카드 형태로 뒤에 겹쳐 보이게 하세요.
별도 ‘지난 일정 N개’ 아코디언이나 요약 헤더를 만들지 마세요.
노출된 뒷 레이어를 누르면 최근 종료 순으로 펼쳐지고 다시 접힙니다. 전면 카드 조작과 터치가 충돌하지 않아야 합니다.
홈과 오늘의 일간 화면에 같은 원리를 적용하고 과거·미래 날짜에는 무조건 적용하지 마세요.
일간은 왼쪽 시작·종료 시간축과 오른쪽 일정 블록으로 구성하고 카드 안의 중복 시간은 제거하세요.
진행 중 컬러 강조, 시간 겹침·일정 사이 공백, 짧은 일정의 최소 높이를 고려하세요.
월간 날짜에서 해당 일간으로 이동하며 별도 주간 캘린더 화면은 만들지 마세요.

## AI와 사용자 승인
추가(+) 첫 화면은 상단 ‘삐꾸에게 부탁하기’와 일정·할 일·루틴 추가 메뉴입니다.
추가 메뉴 AI는 새 항목 생성, 더보기 AI는 선택한 항목 맥락, 등록 폼 AI는 작성 중 초안 보조로 구분하되 AI 화면을 재사용하세요.
직접 입력한 값을 동의 없이 덮어쓰지 말고 AI 초안은 사용자 확인 후 저장하세요.
명시적 미완료 항목의 다시 계획하기는 필요 여부·기한·고정 일정 충돌을 확인한 뒤 시간과 이유, 수락·수정·거절을 제공합니다.
사용자 승인 전 원본은 유지하고 승인 시에도 최신 충돌과 제안 유효성을 재확인하세요.
공동 약속 변경·삭제는 기존 승인 절차를 유지하세요. 연락 승인 상세 디자인은 보류된 항목입니다.

## 진행과 완료 조건
기존 구현과 디자인의 대응 관계·부족한 부분을 간단히 정리한 뒤 홈과 공통 부품부터 적용하세요.
적합한 기존 부품을 확장하고 최소 변경으로 나머지 화면과 실제 상태·API에 연결하세요.
기능에 맞는 빈·로딩·오류·재시도 상태를 보완하세요.
완료·취소·참석 기록 공유, 루틴 규칙 보존, 카드 스택 조작, 월간→일간 이동,
AI 진입 맥락, 제안의 거절·수정·승인 전후 원본 보존을 실제 앱에서 검증하세요.
360·390·430px와 글자 확대에서 제목·버튼·하단 콘텐츠 가림을 확인하세요.
목업 테스트와 실제 앱 테스트를 구분하고 변경 내용·검증 결과·미연결 기능·남은 차이·실행 방법을 보고하세요.
이 자료를 전달받았다는 이유만으로 무관한 코드 게시·PR 병합·운영 배포까지 승인된 것으로 해석하지 마세요.
