## 2. 플로우

- 사용자 선택: 추천 확인과 승인 흐름을 먼저 본다 (structure-2: proposal).
### 시나리오 1 — 추천 확인과 승인 (검토용 초안)
1. 오늘의 일정을 살펴보다가 아직 추가되지 않은 산책 추천을 봅니다. (①)
2. 추천된 시간과 제안 이유를 읽고 기존 일정이 유지되고 있는지 확인합니다. (⑦)
3. 새로 추가할 일정의 내용과 시간을 확인한 뒤 직접 수락할지 결정합니다. (⑨)
4. 사용자가 추가를 선택한 뒤 일정에 반영된 결과를 봅니다. (⑩)
5. 달력에서 같은 날짜에 추가된 산책과 기존 일정을 확인합니다. (③)

- 화면별 primary CTA: 홈 일정에 추가 → ①, 월간 캘린더 날짜 선택 → ②, 일간 캘린더 월간 보기 → ③, AI 비서 메시지 보내기 → ④, 일정 추가 저장 → ⑤, 루틴 추가 → ⑥, 추천 확인 내용 확인 → ⑦, 연락 승인 연락 여부 확인 → ⑧, 추천 승인 확인 일정에 추가 → ⑨, 일정 추가 결과 일정 확인 → ⑩
- CTA 근거: 추천 흐름 첫 장면의 홈 배치는 채팅으로 확인했고 마지막 장면은 괜찮아요를 받았다. 다른 투어 장면은 추가 의견이 없어 현재 버튼을 기본안으로 기록한다. 투어 밖 화면과 아직 만들지 않은 연락 승인은 사용자 확인 전 가정이다.
- 추천이 생성되거나 제안된 것과 일정 반영을 구분한다. 실패·오래된 제안은 반영하지 않는다.
- 사용자 반응 원문 및 전체 루틴 의견은 [feedback-original.md](feedback-original.md)에 보존한다. 시안의 행동은 서버나 AI 연동이 아닌 설명 예시다.

## 6. 1차 사용자 의견 반영

- 화면 목록: 추천대로 수락 (structure-1).
- 루틴: 목록·체크·다시 이어가기 (structure-2: full). 사용자가 제공한 회의 요약에서 루틴 등록·반복 설정·수행 추적·복구를 유지하고, 행동 패턴 분석·퀘스트·보상 등은 확장 후보로 다룬다.
- 다음에 살펴볼 흐름: 추천 확인과 승인 (structure-2: proposal).
- 홈의 날씨 아이콘과 온도·맑음 표시 정렬을 조정하고, 프로필 이미지가 보이는 영역을 수정한다.
- AI 비서 중앙 버튼에 친근한 캐릭터 느낌을 제안한다. 특정 서비스와 같은 캐릭터라고 확정하지 않는다.
- 원문은 feedback-original.md에 보존한다. 사용자 확인 전인 버튼 캐릭터와 상세 화면 모양은 시안이다.

- 해석: 추천 흐름의 첫 장면은 기존 홈 시안과 같은 프로필, 화면 구성, 배치를 사용한다.
- 첫 장면의 프로필과 홈 배치는 수정 후 사용자가 채팅에서 괜찮다고 확인했다. 그 밖의 첫 장면 요소 전체를 별도로 확정한 뜻은 아니다.

## 8. 캘린더와 루틴 화면 사용자 의견

- 원문: feedback-original.md의 sketch-calendar, sketch-routine에 각각 보존한다.
- 캘린더: 월간에서 날짜 선택 시 일간으로 이동하는 방식을 이번 시안의 제안으로 택한다. 달력은 카드 안에 정사각형에 가까운 그리드, 숫자·일정 점·선택 상태만 배치한다. 상세 일정은 일간에서 본다. 별도의 주간 캘린더 화면은 만들지 않는다.
- 루틴: 오늘과 전체를 구분하고 반복 요일에 맞는 항목만 표시한다. 등록·수정·삭제·날짜별 완료/미완료 기록·상세 내역을 살펴볼 수 있게 한다. 아직 기록하지 않음, 예정, 미완료를 구분하고 승인 전에는 추천을 캘린더에 반영하지 않는다.
- 시안의 시작 날짜와 시간은 참조 이미지와 일치하는 2025-04-17 11:01 예시로 명시한다. 실제 현재 시각이나 서버 데이터가 아니다. 추천 시간은 샘플 일정으로 검증하는 예시이며 실제 AI 연결이 아니다.
- 추천 따라가기: scene-1의 프로필과 홈 배치는 수정 후 채팅에서 괜찮다고 확인됨. 이전 수정 요청은 보존함. scene-5는 괜찮아요로 저장됨. scene-2~4의 개별 반응은 없다.

- 홈 레이아웃을 같은 구성 요소로 보여주고, 원본 네 장을 직접 열어 비교할 수 있는 이미지 기준 확인 화면을 준비한다.
- 색감, 카드·간격, 글자, 내비게이션, 달력·루틴에 대한 사용자의 추가 반응을 기다린다. 최종 수치와 디자인 규칙은 아직 확정하지 않는다.

## 11. 일정 상태와 복구 사용자 의견

- 원문은 feedback-original.md에 그대로 보존한다. 같은 내용이 홈과 이미지 기준 의견에 각각 저장되었다.
- 기준: 일정과 할 일은 구분하고, 할 일·루틴은 완료·미완료를 사용자가 기록한다. 미기록을 자동 미완료나 완료로 바꾸지 않는다. 시간이 지난 미기록은 확인 필요로 표시한다. 고정 약속은 완료 체크 대신 상세와 참석 여부를 제공한다.
- 홈 현황의 진행 중은 예시 현재 시각과 시간 범위로 계산하고 완료는 실제 확인 기록만 센다. 완료율은 완료 확인이 가능한 항목을 분모로 표기한다.
- 할 일과 루틴은 미완료를 명시적으로 기록한 경우에만 복구 흐름을 제공한다. 필요 여부와 기한을 먼저 확인하고, 일정 충돌 및 기한 조건을 고려한 예시 제안의 수락 전에 기존 일정은 바뀌지 않는다.
- 홈과 일간의 같은 일정 상태를 공유한다. 루틴의 회차 기록과 반복 규칙은 분리한다. 제안과 승인된 일정을 구분한다.
- 현재는 고정된 예시 시각과 로컬 시안 데이터이며, 실제 AI 및 서버와 연결되었다는 의미가 아니다.

### 일정 상태 시안에 반영한 내용

- 홈과 일간은 같은 할 일·고정 약속 기록을 사용한다. 할 일은 완료 체크와 취소 및 상세에서 미완료 기록을 지원하며, 고정 약속은 참석 여부를 별도로 선택한다.
- 홈의 진행 중은 예시 시간 범위를 기준으로 계산한다. 완료율은 완료를 기록할 수 있는 할 일과 루틴을 분모로 사용하고, 확인된 지난 약속은 남은 항목에서 따로 표시한다.
- 할 일과 루틴은 필요 여부 및 선택적 기한 확인 후, 다른 예시 일정과 겹치지 않고 기한 안에 끝나는 시간만 제안한다. 기한 수정과 시간 수정은 수락 전까지 원본을 바꾸지 않고, 수락 직전 다시 확인한다.
- 승인된 할 일 복구는 출처를 표시하며, 승인된 루틴 복구의 완료 기록은 루틴과 일간 캘린더가 공유한다.
- 위 내용은 독립 미리보기의 로컬 예시 동작이다. 실제 AI와 일정 서버에는 연결되지 않았고, 현재 브라우저에만 저장된다.

## 16. 추가 메뉴와 새 일정 AI 요청

- 원문은 feedback-original.md에 보존한다. 첨부 이미지는 기존 더보기의 AI 강조 카드이며 색·아이콘·여백을 추가 메뉴에도 재사용한다.

- 직접 입력 중 AI 초안은 일정·할 일뿐 아니라 새 루틴 폼에도 제공한다. 미승인 대화와 제안은 브라우저의 초안으로 복구하며 승인 없이 일정에 추가하지 않는다. 이전 절의 새로고침 초기화 안내는 이 기준으로 대체한다.
