# 삐꾸 디자인 전달 메모

Figma 원본: https://www.figma.com/design/YpAuzE5kCYzo6AQ3a59jmE

이 문서는 iOS·Android 삐꾸 디자인 시안을 기존 앱 코드와 아키텍처에 적용할 때 참고하기 위한 메모다. 팀원이 복제본을 사용할 경우 위 주소 대신 복제본 주소를 전달한다. 실제 앱의 코드, 기술 스택, 데이터 모델과 현재 PRD를 먼저 확인하고 충돌하는 결정은 확인한다.

## Figma 구성

- `03 Screens`: 검토한 기본 화면과 일정 등록·완료·더보기·루틴 복구 등의 예시 화면.
- `02 Components`: 일정 카드 8개 변형, 일정 상태 버튼 5개 변형, 일반 행동 버튼 3개 변형, 하단 내비게이션과 사용 예시.
- 카드 텍스트는 인스턴스 속성에서 바꿀 수 있다. 목록형과 일간 타임라인형은 시간 정보 배치가 다르다.
- **기존 화면의 일정 카드와 버튼은 새 공통 부품으로 교체되지 않았다.** 공통 부품과 사용 예시는 별도이며, 화면 연결 작업이 남아 있다.
- 프리텐다드를 적용할 예정이다. Figma 작성 환경에서 발견되지 않아 현재는 Noto Sans KR을 사용한다. 프로필은 임시 표현이다.
- Figma의 화면 전환은 예시이며 실제 서버, AI, 일정 데이터와 연결되어 있지 않다. 실제 기기와 빈·오류 화면은 추가 검증이 필요하다.

## UI와 동작에서 지킬 내용

- 하단 내비게이션은 홈 / 캘린더 / AI 비서 / 추가 / 루틴을 사용한다.
- 일정·할 일·루틴 카드는 제목, 시간 또는 상태, 색상 구분선, 상태 버튼과 더보기로 구성한다. 할 일과 루틴은 완료 기록을, 약속과 회의는 참석 여부를 관리한다.
- 시간이 지났다는 이유로 완료·미완료·불참을 자동 기록하지 않는다. 완료는 취소할 수 있어야 하며 동일한 날짜의 기록은 화면 간 일관되게 표시한다.
- 루틴의 날짜별 수행 기록과 반복 규칙을 분리한다. 하루 기록을 바꿔도 반복 규칙 자체는 바꾸지 않는다.
- 지난 일정이 있는 오늘 화면은 현재 또는 다음 일정 뒤에 카드가 겹쳐 보이고, 레이어를 눌러 개별 일정을 볼 수 있는 방향이다. 과거·미래 날짜는 해당 날짜 기록을 확인하는 데 맞춘다.
- 사용자가 명시적으로 미완료를 기록한 항목은 다시 계획을 요청할 수 있다. 제안은 필요 여부, 기한, 충돌을 확인한 뒤 보여주며 사용자가 수락하기 전에는 실제 일정을 바꾸지 않는다.
- 공동 일정의 연락 승인 화면은 보류 중이다. 기존 서비스의 승인 규칙을 확인하고 임의로 연락하거나 변경하지 않는다.
- 카드와 버튼의 터치 영역은 최소 44×44를 목표로 하고, 긴 제목 및 360·390·430px 화면에서 잘림과 겹침을 확인한다.

## 팀원 AI에게 전달할 문장

> 삐꾸 디자인 시안을 기존 프로젝트에 적용해 주세요. Figma 링크와 이 메모를 참고하되 기존 코드와 아키텍처를 먼저 확인하고, 실제 데이터·상태 흐름에 맞춰 합쳐 주세요. 03 Screens는 화면 방향이고 02 Components는 카드와 버튼의 공통 부품 초안입니다. 기존 화면이 새 Figma 부품에 아직 연결되지는 않았습니다. 수행 상태와 참석 여부, 루틴 날짜별 기록, AI 제안의 사용자 승인 조건은 위 메모대로 유지해 주세요. 실제 동작과 테스트 결과, 남은 차이를 구분해서 알려 주세요.
