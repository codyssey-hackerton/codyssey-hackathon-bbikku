# 삐꾸 — 루틴 탭 관련 아이데이션 및 회의 내용 총정리

2026년 10월 30\~31일 진행한 삐꾸(AI 개인화 일정 추천 비서) 관련 대화, 초기 회의록, 통합 회의록, PRD에서 루틴과 연결되는 내용을 모았습니다.

먼저 핵심부터 정리하면, 우리가 논의했던 루틴 탭은 단순히 반복 일정을 등록하는 공간이 아니라, 사용자의 반복적인 생활 패턴을 관리하고, 루틴을 실행하지 못했을 때 AI가 다시 이어갈 수 있도록 지원하는 기능에 가깝습니다.

특히 기존 아이데이션에는 다음 세 가지 개념이 함께 등장했습니다.

- 루틴 관리: 운동, 공부, 출근 등 반복되는 활동을 등록하고 관리.
- 생활 패턴 학습: 반복 행동과 선호도를 기반으로 AI가 새로운 루틴을 제안.
- 루틴 복구: 실행하지 못한 루틴이나 미완료 작업을 보존하고, 가능한 시간에 다시 추천.

다만 통합 회의록의 기능 목록은 아이디어를 빠뜨리지 않고 보존하기 위한 것으로, 모든 기능이 MVP 개발 범위로 확정된 것은 아닙니다.

| ----- | ----------- |

## 2. 루틴에 직접 관련된 유저스토리 원문

### US-09 — 반복 루틴 등록과 복구

> 규칙적으로 운동하거나 공부하는 사용자로서 나는 내 반복 루틴을 등록하고, 루틴을 지키지 못했을 때 다시 이어갈 수 있도록 도움받고 싶다.

관련 기능으로 기록된 것은 루틴 등록·수정, 요일 및 시간 설정, 루틴 탭, 반복 활동 추적, 수행 여부 기록, 중단된 루틴 복구 추천입니다.

### US-08 — 미완료 작업 복구

> 전날 하지 못한 운동, 장보기, 공부, 서류 작성 등을 잊지 않고 다시 이어가고 싶다.

관련 흐름은 다음과 같습니다.

활동 완료 여부 기록

미완료 작업 보존

다음 날 빈 시간 및 일정 확인

AI 재배치 추천

반복 실패 시 다른 대안 제시

핵심은 미완료 활동을 단순히 다음 날로 복사하는 것이 아니라, 그 활동이 여전히 필요한지 확인하고 실제로 실행할 수 있는 시간을 찾아주는 것입니다.

### 관련 사용자 맥락도 논의됐습니다

US-01 — 온보딩: 사용자의 생활 패턴, 활동 목적, 루틴, 자주 가는 장소 등을 필요한 만큼 수집하고 나중에 수정할 수 있게 하는 방향입니다.

US-02 — 다음 날 계획: 저녁에 내일과 이후의 일정을 검토할 때 반복적인 생활 패턴과 빈 시간, 식사, 휴식 등을 함께 고려하는 방향입니다.

US-10 — 개인화: 명시적인 선호, 실제 행동 기록, 이전 추천의 승인·거절 이력을 구분해서 활용하는 방향입니다.

US-13 — 회고: 하루의 활동과 목표 대비 결과를 확인하고 이후 일정 계획을 개선하는 방향입니다.

US-14 — 동기부여: 퀘스트와 보상 등으로 사용자가 행동을 지속할 수 있도록 하는 방향입니다.

## 4. 루틴 탭과 관련해서 실제 논의됐던 사용 시나리오

시나리오 A — 운동 루틴을 놓친 학생

정기적인 운동을 하지 못했지만 오전 9시 학교 일정은 유지해야 하는 상황입니다. AI는 학교 일정을 보호하고, 운동을 다시 할 수 있는 시간을 제안합니다. 변경은 사용자 승인 후에만 반영합니다.

시나리오 B — 전날 작업을 완료하지 못한 사용자

장보기, 공부, 서류 작성 등의 미완료 작업을 다음 날에도 기억하고, 기한과 필요 여부를 확인해 다시 일정에 배치하는 상황입니다.

시나리오 C — 반복 행동에서 새로운 루틴 발견

사용자가 반복하는 활동을 바탕으로 AI가 루틴 등록을 제안합니다. 다만 몇 번 반복해야 제안할 것인지는 결정되지 않았습니다.

시나리오 D — 피곤하거나 계획이 어긋난 날

사용자의 현재 컨디션과 고정 일정을 고려해서 작업을 유지할지, 휴식하거나 다른 시간으로 옮길지 제안합니다. 루틴에도 적용할 수 있는 공통 재계획 아이디어입니다.

## 5. 루틴과 관련해서 논의했던 페인포인트

10월 30일 페인포인트 관련 대화에서는 사용자가 루틴을 지속하지 못하는 이유를 검토했습니다.

| 문제 원인            | 루틴 기능과 연결되는 방향   |
| ---------------- | ---------------- |
| 계획을 세우는 부담       | AI가 실행 가능한 계획 제안 |
| 시작하기 어려움         | 다음에 해야 할 행동 안내   |
| 비현실적인 목표         | 시간·일정 제약을 반영한 계획 |
| 갑작스러운 일정 변경      | 영향을 받는 활동만 재추천   |
| 보상·동기 부족         | 퀘스트·보상 아이디어      |
| 실패 후 다시 복귀하기 어려움 | 중단된 루틴 복구 추천     |

여기서 가장 중요했던 문제 인식은 계획의 수립뿐 아니라 실행·조정·복귀 과정에도 부담이 있다는 점이었습니다.

다만 이 여섯 가지는 문제 원인으로 검토한 항목이지, 실제 사용자 조사를 통해 모두 검증한 결과라는 뜻은 아닙니다.

특히 중요한 정책은 다음 두 가지입니다.

첫째, 특정 날짜에 루틴을 수행하지 못했다고 반복 규칙 전체를 없애서는 안 됩니다.

또한 현재 PRD에서는 루틴 탭을 반드시 별도 화면으로 구현할지 확정하지 않았으며, 반복 일정의 전체 편집과 행동 관측 기반 자동 학습은 첫 개발 범위에서 제외했습니다.

## 월간 캘린더 (sketch-calendar)

현재 월간 캘린더 화면 방향은 좋지만, 몇 가지를 꼭 수정했으면 좋겠습니다.

1. **월간 + 일간 구조를 함께 고려해주세요.**
현재는 월간 캘린더만 보이고, 날짜를 눌렀을 때 이어지는 **일간 화면 구조가 보이지 않습니다.**
삐꾸에서는 월간과 일간이 함께 작동해야 하므로,
- 월간 화면에서 날짜를 선택하면
- 해당 날짜의 **일간 일정 화면으로 자연스럽게 이동하는 구조**
를 전제로 디자인해주세요.

즉, “월간 보기”와 “일간 보기”가 따로 분리된 것이 아니라,
**월간 → 특정 날짜 선택 → 일간 상세로 진입**
하는 흐름이 화면 설계에 반영되면 좋겠습니다.

2. **캘린더 레이아웃과 크기를 더 안정적으로 맞춰주세요.**
현재 달력 영역이 카드 안에서 약간 삐져나오거나 비율이 어색해 보여서 전체 완성도가 떨어집니다.
달력은 카드 안에서 여백이 일정하게 유지되도록 정리해주시고,
상단 월 표시, 좌우 이동 버튼, 요일 헤더, 날짜 셀 간격이 균형 있게 맞으면 좋겠습니다.

3. **달력 셀은 정사각형에 가까운 구조가 좋겠습니다.**
현재처럼 셀 비율이 조금 불안정하면 달력이 복잡해 보일 수 있어서,
**날짜 칸을 최대한 정사각형 그리드 구조**로 맞추는 방향을 추천합니다.
정사각형 또는 거의 정사각형에 가까운 셀 구조로 가면
- 월간 화면이 더 안정적으로 보이고
- 날짜 선택 상태도 더 깔끔하게 강조할 수 있습니다.

4. **월간 캘린더는 정보량을 줄이고 깔끔하게 보여주세요.**
월간 화면에서는 너무 많은 정보를 한 칸 안에 넣기보다,
- 날짜 숫자
- 일정 유무를 보여주는 작은 점 표시
- 선택된 날짜 강조
정도로 단순하게 보여주는 것이 좋겠습니다.

상세한 일정 내용은 월간 셀 안에 다 넣기보다,
하단의 “다가오는 주요 일정” 카드나
선택한 날짜의 일간 화면에서 보여주는 구조가 더 깔끔할 것 같습니다.

5. **선택한 날짜와 연결되는 일간 화면 흐름을 함께 보여주세요.**
예를 들어 4월 17일을 누르면
- 선택 상태가 월간 화면에서 강조되고
- 아래에 해당 날짜 주요 일정 미리보기 카드가 나타나거나
- 탭/전환 애니메이션으로 일간 화면으로 넘어가는 방식
중 하나로 연결되면 좋겠습니다.

개인적으로는
**월간 화면에서 날짜 선택 → 아래에 그 날짜 일정 미리보기 → 더 자세히 보면 일간 화면 진입**
또는
**날짜 선택 즉시 일간 화면으로 전환**
두 가지 방식 중 하나로 설계해주시면 좋겠습니다.

6. **레퍼런스 이미지 톤은 유지하되 달력 컴포넌트는 더 정제된 구조로 다듬어주세요.**
현재 전체 색감과 카드 스타일은 좋습니다.
다만 달력 자체는 좀 더 정돈된 UI가 필요합니다.
월간 달력은 너무 장식적이기보다
**깔끔한 그리드형 캘린더**로 정리하고,
선택한 날짜와 AI/일정 연결 흐름이 명확하게 보이면 좋겠습니다.

정리하면,
- 월간 캘린더만 있는 것이 아니라 **일간 화면까지 연결되는 구조**
- 날짜 선택 시 **일간 화면으로 이어지는 UX**
- 달력은 카드 안에서 **정사각형 그리드 기반으로 안정적으로 정렬**
- 월간에서는 간단히, 상세 내용은 일간에서 보여주는 방식
으로 수정해주세요.

## 루틴 화면 (sketch-routine)

현재 루틴 화면의 전체적인 색감, 카드 디자인, 여백, 하단 내비게이션은 마음에 듭니다. 첨부한 레퍼런스 이미지와 동일한 톤앤매너를 유지하면서 루틴 관리 기능과 실제 사용자 흐름을 조금 더 구체화해주세요.

**1. 오늘의 루틴과 전체 루틴 구분**
- 현재 화면에는 오늘의 루틴만 표시되어 있는데, 사용자가 등록한 전체 루틴도 확인할 수 있어야 합니다.
- '오늘의 루틴'과 '전체 루틴'을 구분해서 볼 수 있도록 구성해주세요.
- 전체 루틴에서는 반복 요일, 시간, 수행 상태를 확인하고 수정·삭제할 수 있어야 합니다.
- 루틴을 누르면 상세 화면으로 이동하도록 해주세요.

**2. 루틴 등록·수정 화면 추가**
- 루틴 이름, 반복 요일, 시작 시간, 예상 소요시간, 목표 등을 설정할 수 있도록 해주세요.
- 매일 반복, 특정 요일 반복 등을 지원해주세요.
- 루틴 추가 버튼을 누르면 등록 화면이나 바텀시트가 열리도록 해주세요.
- 기존 루틴도 수정·삭제할 수 있어야 합니다.

**3. 반복 요일과 수행 상태의 논리 수정**
- 현재 목요일이 선택되어 있는데 월·수·금에 반복되는 아침 운동이 오늘의 루틴으로 표시됩니다. 선택한 날짜의 반복 규칙에 맞는 루틴만 오늘 목록에 표시해주세요.
- 상단 완료율과 루틴 개수도 해당 날짜에 실제로 예정된 루틴을 기준으로 계산해주세요.
- 화면에 표시하는 날짜와 현재 시간은 실제 앱 상태에 맞춰 일관되게 처리해주세요.
- 사용자가 특정 날짜의 루틴을 완료하거나 미완료로 표시해도 반복 규칙 자체는 유지되어야 합니다.

**4. AI 루틴 복구 기능 개선**
삐꾸의 핵심 차별점은 루틴을 실패했을 때 다시 실행할 수 있도록 AI가 도와주는 것입니다.

- 예정 시간이 아직 지나지 않은 루틴은 미완료 또는 실패로 단정하지 말아주세요.
- 실제로 놓친 루틴과 아직 실행 전인 루틴을 구분해주세요.
- 루틴을 놓친 경우 '다시 계획하기' 버튼을 보여주세요.
- 버튼을 누르면 AI가 기존 일정, 고정 약속, 빈 시간, 루틴 소요시간을 고려해 실행 가능한 다른 시간을 추천하도록 해주세요.
- 추천 시간과 추천 이유를 함께 보여주세요.
- 수락·수정·거절 버튼을 제공하고, 사용자가 승인한 경우에만 일정에 반영해주세요.
- 기한이 지나거나 더 이상 필요하지 않은 루틴은 무조건 다음 날로 옮기지 말고 사용자에게 확인해주세요.

**5. 루틴 수행 기록과 달성률**
- 상단 '나의 작은 습관들' 영역은 유지해주세요.
- 오늘의 루틴 달성률과 전체 개수를 직관적으로 확인할 수 있도록 해주세요.
- 선택한 날짜별로 완료·미완료 기록을 확인할 수 있어야 합니다.
- 가능하다면 루틴 상세 화면에서 최근 수행 기록과 달성률을 확인할 수 있도록 해주세요.
- 기록이 없는 날짜와 실제 미완료로 확인된 날짜는 구분해주세요.

**6. 날짜 선택 영역 개선**
- 현재 상단의 일주일 날짜 선택 UI는 유지해도 좋습니다.
- 선택한 날짜에 맞춰 아래 루틴 목록과 완료 상태가 변경되도록 해주세요.
- 캘린더 탭의 주간 보기는 필요 없지만, 루틴 탭에서 날짜별 수행 기록을 확인하기 위한 가로형 7일 선택 UI는 유지해도 됩니다.
- 날짜 선택 상태와 오늘 날짜를 시각적으로 구분해주세요.

**7. 루틴 카드 디자인**
- 현재 카드 디자인을 유지하면서 루틴 이름, 반복 요일, 실행 시간, 소요시간, 상태를 명확하게 보여주세요.
- 완료·예정·미완료 상태를 시각적으로 구분해주세요.
- 체크 버튼은 누르기 편한 크기로 구성하고 카드 전체를 누르면 루틴 상세 화면으로 이동하도록 해주세요.
- AI가 복구를 추천한 루틴은 일반 루틴 카드와 구분해 보여주세요.

**8. 핵심 사용자 흐름**
루틴 탭에서 다음 흐름을 확인할 수 있도록 구성해주세요.

루틴 추가 → 반복 요일과 시간 설정 → 오늘의 루틴 확인 → 완료 체크 → 루틴 미수행 발생 → AI 복구 시간 제안 → 추천 이유 확인 → 사용자 승인 → 캘린더 및 루틴 상태 반영

이번에는 전체적인 디자인을 새로 바꾸기보다는 현재 시안의 완성도를 유지하면서 루틴 등록·상세·수행 기록·AI 복구 흐름을 실제로 사용할 수 있는 구조로 구체화해주세요.

## 일정 상태와 미완료 복구 추가 의견 (sketch-home / style-reference)

첨부한 레퍼런스 이미지의 디자인 방향은 유지해주세요. 연한 라일락·블루 배경, 흰색 둥근 카드, 색상별 일정 구분, 하단 내비게이션과 AI 비서 강조 버튼이 마음에 듭니다.

다만 일정 카드의 기능은 단순한 체크 버튼 하나로 끝나지 않도록 개선하고 싶습니다.

**1. 일정·할 일·루틴의 수행 상태**

할 일과 루틴에서는 사용자가 완료 여부를 기록할 수 있어야 합니다.

상태는 예정, 완료, 미완료, 확인 필요를 구분하고, 사용자가 아무것도 선택하지 않았다는 이유로 미완료로 처리하지 말아주세요.

빠른 완료 체크는 카드 오른쪽의 원형 버튼으로 유지하고, 추가 행동은 카드 상세 또는 더보기 메뉴에서 선택하도록 구성해주세요.

완료 처리 후에는 상태가 즉시 반영되고, 잘못 눌렀을 때 완료를 취소할 수도 있어야 합니다.

고정 약속은 일반 할 일이나 루틴과 성격이 다르므로 모든 일정 카드에 동일한 완료 체크를 강제하지 말고, 상세 정보와 필요시 참석 여부 확인을 제공해주세요.

**2. 미완료 작업의 AI 복구**

사용자가 작업이나 루틴을 실제로 수행하지 못했다고 기록하면 '다시 계획하기' 기능을 제공해주세요.

AI는 해당 작업이 아직 필요한지, 기한이 유효한지, 다른 고정 일정과 충돌하지 않는지 확인한 후 가능한 시간을 추천하도록 해주세요.

추천 카드에는 새로운 시간, 추천 이유, 수락·수정·거절 버튼을 포함해주세요.

미완료 체크만으로 기존 일정을 자동 변경해서는 안 됩니다. 사용자가 승인한 제안만 실제 일정에 반영해야 합니다.

**3. 홈 화면의 진행 현황**

오늘의 일정 현황에서는 완료·진행 중·남은 항목을 명확하게 구분해주세요.

진행 중은 현재 시간과 일정 시간을 기준으로 표현하되, 시간이 지났다고 자동으로 완료 처리하지는 말아주세요.

완료율은 실제로 완료가 확인된 항목을 기준으로 계산해주세요. 확인되지 않은 항목을 임의로 완료나 실패에 포함하지 않도록 해주세요.

**4. 화면 간 상태 연결**

홈에서 완료 체크한 내용이 일간 캘린더에도 동일하게 반영되어야 합니다.

루틴은 특정 날짜의 수행 상태와 전체 반복 규칙을 분리하고, 하루 미완료가 반복 규칙 자체를 변경하지 않도록 해주세요.

AI가 제안한 계획은 기존 일정과 시각적으로 구분하고 승인 이후에만 확정된 일정으로 표시해주세요.

**5. 시각적 디자인**

현재 레퍼런스의 부드러운 색상과 카드 스타일은 그대로 유지해주세요.

모든 상태에 별도의 큰 버튼을 나열하기보다 기본 카드에서는 제목·시간·상태·핵심 행동만 보여주고, 상세 기능은 카드 선택이나 바텀시트로 제공해주세요.

전체적으로 복잡한 일정 관리 앱보다는 사용자가 쉽게 실행을 기록하고, 어려운 상황에서는 AI에게 도움을 받을 수 있는 개인 비서 느낌으로 구성해주세요.

이번 단계에서는 기존 디자인 톤을 바꾸기보다 일정 카드의 상태 표현, 완료 체크, 미완료 복구, AI 제안과 사용자 승인 흐름을 더 명확하게 만들어주세요.

## 일정 카드 버튼과 더보기 메뉴 통일 의견 (sketch-home)

현재 홈 화면의 전체적인 디자인과 색감, 카드 스타일은 유지해주세요. 다만 일정 카드들의 버튼 구성과 조작 방식이 서로 달라서 사용자 경험을 통일하고 싶습니다.

**1. 모든 일정 카드의 버튼 구조 통일**

현재 일부 일정에는 체크 버튼이 있고, 일부 일정에는 화살표만 표시되어 있습니다. 일정·할 일·루틴 모든 카드에 일관된 조작 구조를 적용해주세요.

각 카드 오른쪽에는 두 가지 기능을 배치해주세요.

- 상태 확인 버튼: 완료 또는 참석 여부 등을 기록하는 버튼
- 더보기 버튼(세로 점 3개): 상세 보기, 수정, 삭제 및 추가 행동을 선택하는 메뉴

기존 화살표 아이콘과 체크 버튼이 혼용되는 구조는 개선해주세요.

**2. 체크 버튼 디자인 개선**

현재 원형 체크 아이콘만 있는 방식보다는 아이콘과 짧은 텍스트를 함께 사용하거나, 둥근 형태의 작은 버튼에 '완료', '완료됨', '참석 확인' 등의 문구를 넣어주세요.

예시:
- 할 일: '완료' → 선택 후 '완료됨'
- 루틴: '완료' → 선택 후 '완료됨'
- 약속·회의: '참석 확인' → 참석·불참·미확인 선택

완료된 항목은 체크 아이콘과 색상으로 명확하게 표시하고, 아직 완료하지 않은 항목은 너무 강조되지 않은 아웃라인 버튼으로 보여주세요.

버튼 크기와 간격은 실제 모바일 환경에서 누르기 편하도록 구성해주세요.

**3. 더보기 버튼 기능**

모든 카드 오른쪽 끝에 세로 점 3개(···) 아이콘을 동일한 크기와 위치로 배치해주세요.

더보기를 누르면 바텀시트가 열리고 다음 행동을 선택할 수 있도록 구성해주세요.

- 상세 정보 보기
- 일정·할 일·루틴 수정
- 삭제
- 완료 상태 변경
- 다시 계획하기(AI 추천)

다만 모든 항목에 무조건 동일한 메뉴를 보여주기보다는 일정 유형과 현재 상태에 따라 필요한 행동만 제공해주세요.

고정 약속이나 타인이 참여하는 일정은 임의로 수정·삭제하지 않도록 사용자 확인과 기존 승인 규칙을 유지해주세요.

**4. 일정 유형에 따른 상태 구분**

일정, 할 일, 루틴은 성격이 다르므로 상태 기록의 의미도 구분해주세요.

- 할 일·루틴은 완료·미완료·미확인 상태 관리
- 약속·회의는 참석·불참·미확인 상태 관리
- 현재 시각을 기준으로 진행 중인지 표시하되, 시간이 지났다는 이유로 완료나 불참으로 자동 처리하지 않기

예를 들어 '앨리스와 브런치'는 고정 약속이므로 오른쪽 상태 버튼에서 참석 여부를 확인할 수 있어야 하고, 더보기에서는 상세 정보와 수정 기능에 접근할 수 있어야 합니다.

**5. 상태 버튼을 눌렀을 때의 동작**

할 일·루틴의 '완료' 버튼을 누르면 해당 항목만 완료 처리하고 홈·캘린더·루틴 화면에 즉시 반영해주세요.

잘못 완료한 경우에는 취소할 수 있어야 합니다.

사용자가 '못했어요' 또는 '미완료'를 선택한 경우에는 미완료로 기록하고, 필요하다면 'AI로 다시 계획하기'를 선택할 수 있도록 해주세요.

미완료를 기록했다고 AI가 자동으로 일정을 변경하면 안 됩니다. AI는 새로운 시간을 제안하고 사용자의 승인 후에만 변경을 반영해야 합니다.

**6. 카드 디자인과 레이아웃**

기존의 블루·라일락 배경, 둥근 화이트 카드, 색상별 구분선은 유지해주세요.

일정 카드 내부는 다음처럼 통일하면 좋겠습니다.

왼쪽: 일정 유형별 색상 구분선
중앙: 일정 제목, 시간, 유형 및 현재 상태
오른쪽: 상태 버튼 + 더보기 아이콘

현재 상태가 중복으로 표시되지 않도록 해주세요. 예를 들어 완료 버튼에 '완료됨'이라고 표시되어 있다면 카드 아래에 동일한 '완료' 텍스트를 반복하지 않아도 됩니다.

기존 카드의 크기를 과도하게 키우지 않고, 버튼을 추가해도 제목과 시간이 잘리지 않도록 간격을 정리해주세요.

**7. 전체 화면 일관성**

이 버튼 구조는 홈 화면뿐 아니라 일간 캘린더와 루틴 화면에도 일관되게 적용해주세요.

월간 캘린더는 날짜 탐색 중심이므로 카드 버튼을 모두 노출하지 않아도 됩니다. 날짜를 선택해 일간 화면에 진입하면 동일한 카드 조작 방식을 사용할 수 있도록 해주세요.

이번 수정은 전체 디자인을 다시 만드는 것이 아니라, 기존 시안의 디자인을 유지하면서 모든 일정 카드의 상태 관리와 추가 행동을 명확하고 일관되게 만드는 작업입니다.

## 삐꾸에게 부탁하기와 버튼 크기 의견 (sketch-home, 2026-11-01)

완료됨 버튼이 너무 커요 위 아래 여백이 너무 넓어요.

현재 두 번째 이미지의 더보기 바텀시트에 AI 관련 기능을 추가하고 싶습니다.

삐꾸는 단순한 일정 관리 앱이 아니라 AI 개인 비서 서비스이므로, 사용자가 개별 일정이나 루틴을 선택했을 때 해당 내용을 AI에게 바로 물어보거나 작업을 요청할 수 있어야 합니다.

**1. '삐꾸에게 부탁하기' 기능 추가**

더보기 메뉴의 가장 상단에 '삐꾸에게 부탁하기' 기능을 추가해주세요.

반짝이는 AI 아이콘과 연한 블루·라일락 배경을 활용해 일반 메뉴와 시각적으로 구분하고 싶습니다.

이 기능을 선택하면 AI 비서 대화 화면으로 이동하며, 사용자가 선택했던 일정이나 루틴의 정보가 대화 맥락에 자동으로 전달되도록 구성해주세요.

**2. 선택한 일정에 대한 AI 대화**

예를 들어 '물 한 잔 마시기' 루틴의 더보기에서 AI에게 부탁하기를 선택하면, AI가 어떤 루틴을 선택했는지 이해한 상태로 대화를 시작하도록 해주세요.

사용자는 다음과 같은 요청을 할 수 있어야 합니다.

- "이거 다른 시간으로 옮겨줘."
- "오늘 못 했는데 다시 할 시간을 추천해줘."
- "이 루틴 시간을 바꾸는 게 좋을까?"
- "내 다른 일정이랑 겹치는지 확인해줘."
- "이 루틴을 매일 아침으로 변경해줘."

회의·약속을 선택했다면 해당 일정의 시간 변경, 준비시간 계산, 다른 일정과의 충돌 확인 등을 AI에게 요청할 수 있어야 합니다.

선택한 일정의 제목, 날짜, 시간, 종류, 식별 정보를 AI 대화로 전달하여 사용자가 같은 정보를 다시 설명하지 않아도 되도록 해주세요.

**3. AI 화면 진입 방식**

'삐꾸에게 부탁하기'를 선택하면 기존 AI 비서 채팅 화면으로 이동하되, 상단에 현재 선택한 일정이 작은 카드 형태로 표시되면 좋겠습니다.

예시:
선택한 일정: 물 한 잔 마시기 · 오늘 오전 8:00

그 아래에는 해당 일정에 맞는 추천 질문을 2~3개 정도 제공하고, 사용자가 직접 메시지를 작성할 수도 있도록 해주세요.

이때 추천 질문을 누르거나 메시지를 보내야 AI 요청이 실행되도록 하고, 단순히 메뉴를 열었다는 이유로 일정이 변경되지는 않도록 해주세요.

**4. AI 추천과 사용자 승인**

AI가 일정 변경이나 루틴 재조정을 제안하면 새로운 시간과 이유를 보여주고, 사용자가 수락·수정·거절할 수 있도록 해주세요.

사용자가 승인하기 전에는 기존 일정을 변경하지 않아야 합니다.

다른 사람이 참여하는 공동 약속의 경우에는 상대방 연락과 동의가 필요한 상황을 별도로 안내해주세요.

**5. 기존 메뉴와 디자인 유지**

기존의 상세 정보 보기, 수정, 삭제, 완료 상태 변경 기능은 그대로 유지해주세요.

다만 AI 기능이 가장 먼저 보이도록 다음 순서를 추천합니다.

1. 삐꾸에게 부탁하기 — AI 강조 카드
2. 상세 정보 보기
3. 수정
4. 완료 상태 변경
5. 삭제

기존의 둥근 바텀시트, 부드러운 색감, 여백과 타이포그래피는 유지하고, AI 기능만 자연스럽게 추가해주세요.

이번 수정의 핵심은 사용자가 어떤 일정이나 루틴을 보고 있더라도 그 자리에서 바로 AI에게 도움을 요청할 수 있게 만드는 것입니다.

## 지난 일정 스택 의견 (style-reference, 2026-11-01)

현재 삐꾸(PIKKU)의 홈 화면과 일간 캘린더 디자인은 유지하면서, 첨부한 레퍼런스 이미지처럼 **이미 지나간 일정들이 뒤쪽에 겹쳐 있는 듯한 '지난 일정 스택 카드(Collapsed Past Schedule Stack)' UI**를 추가해주세요.

핵심은 지난 일정을 삭제하거나 완전히 숨기는 것이 아니라, 현재 진행 중이거나 앞으로 해야 할 일정에 집중할 수 있도록 지난 일정들을 뒤에 접어두고, 사용자가 누르면 다시 펼쳐 볼 수 있는 구조입니다.

## 1. 적용 화면

다음 두 화면에 동일한 UX를 적용해주세요.

- 홈 화면: 오늘의 일정 목록
- 일간 캘린더: 선택한 날짜의 시간대별 일정 목록

월간 캘린더는 기존 달력 구조를 유지하고, 날짜를 선택하면 해당 날짜의 일간 화면으로 이동하도록 해주세요.

## 2. 지난 일정 판단 기준

현재 시간과 각 일정의 시작·종료 시간을 기준으로 구분해주세요.

- **예정:** 아직 시작하지 않은 일정
- **진행 중:** 시작 시각은 지났지만 종료 시각이 지나지 않은 일정
- **지난 일정:** 종료 시각이 현재보다 이전인 일정
- **완료:** 사용자가 실제 완료했다고 기록한 일정
- **미완료:** 사용자가 직접 수행하지 못했다고 기록한 일정
- **확인 필요:** 시간이 지났지만 사용자가 완료 여부를 기록하지 않은 일정

시간 경과와 수행 상태는 서로 다른 개념으로 처리해주세요.

예를 들어 오전 9시 운동이 오전 10시에 끝났더라도 사용자가 완료 여부를 기록하지 않았다면 자동으로 완료 또는 미완료 처리하지 않고 '확인 필요' 상태를 유지해주세요.

이미 완료된 일정이라도 시간이 지나지 않았다면 무조건 지난 일정 스택으로 이동시키지 말고, 실제 시간 정보를 기준으로 분류해주세요.

종료 시간이 없는 할 일은 마감이나 사용자가 지정한 수행 시간 등을 고려하되, 판단이 불가능하면 임의로 지난 일정으로 분류하지 말아주세요.

## 3. 지난 일정 스택 카드 디자인

첨부한 이미지에서 표시한 것처럼 지난 일정들이 메인 카드 뒤에 여러 장 겹쳐져 있는 듯한 레이어 구조로 표현해주세요.

- 2~3장의 카드가 뒤쪽으로 조금씩 겹쳐져 보이는 형태
- 뒤에 있는 카드는 살짝 축소되거나 위치가 어긋나 보이도록 구성
- 부드러운 그림자와 약간의 투명도 차이로 깊이감 표현
- 기존 화이트 카드와 블루·라일락 색상 유지
- 카드가 여러 장 쌓여 있다는 것을 쉽게 알아볼 수 있는 디자인
- 너무 많은 카드가 겹치거나 텍스트가 잘려 보이지 않도록 구성

접힌 상태에서는 전체 지난 일정 개수와 간단한 상태 요약을 표시해주세요.

예시:
- 지난 일정 3개
- 오늘 지나간 일정 보기
- 완료 2개 · 확인 필요 1개

우측에는 아래쪽 화살표(chevron-down) 아이콘을 배치해서 펼칠 수 있다는 사실을 알려주세요.

지난 일정이 하나만 있을 때도 해당 영역에서 확인할 수 있도록 하되, 여러 장의 카드가 있는 것처럼 과장된 레이어를 만들지는 말아주세요.

## 4. 지난 일정 펼치기·접기 인터랙션

사용자가 접힌 스택 카드를 누르면 이전 일정들이 자연스럽게 펼쳐지도록 해주세요.

**접힌 상태**
- 지난 일정들이 카드 스택처럼 겹쳐 보임
- 전체 개수와 수행 상태 요약 표시
- 현재 진행 중이거나 앞으로 남은 일정이 우선적으로 보임

**펼쳐진 상태**
- 스택이 부드럽게 펼쳐지면서 지난 일정이 개별 카드로 표시됨
- 가장 최근에 종료된 일정이 위쪽에 오도록 정렬
- 각 카드에는 일정 제목, 시간, 일정 유형, 완료·미완료·확인 필요 상태 표시
- 기존 일정 카드와 동일한 상태 버튼 및 더보기 버튼 제공
- 지난 일정을 눌러 상세 정보를 확인하거나 완료 여부를 수정할 수 있음
- 상단의 '지난 일정 접기' 버튼 또는 위쪽 화살표로 다시 접을 수 있음

예시 정렬:
1. 오전 10:30 종료 — 앨리스와 브런치
2. 오전 9:00 종료 — 아침 운동
3. 오전 8:00 종료 — 아침 정리

펼치기·접기는 가능하다면 바텀시트보다 해당 위치에서 카드가 확장되는 아코디언 방식으로 구현해주세요.

부드러운 애니메이션을 적용하되 과도한 움직임이나 복잡한 전환 효과는 피해주세요.

## 5. 홈 화면 정보 배치

홈 화면에서는 사용자가 지금 해야 할 행동을 먼저 파악할 수 있도록 다음 순서로 구성해주세요.

1. 상단 인사말, 날짜, 사용자 프로필
2. 전체·개인·업무 필터
3. 오늘 일정 요약 및 진행 현황
4. 현재 시각과 다음 행동 안내
5. 삐꾸 AI 추천 카드
6. 진행 중이거나 앞으로 남은 일정 목록
7. 지난 일정 스택 카드

현재 카드들의 전체적인 디자인과 색감은 그대로 유지해주세요.

지난 일정 스택은 앞으로 남은 일정 목록 아래에 배치하되, 사용자가 스크롤하면 자연스럽게 확인할 수 있도록 해주세요.

하단 내비게이션과 겹치지 않도록 충분한 스크롤 여백을 확보해주세요.

## 6. 일간 캘린더 적용

일간 캘린더에서도 동일한 지난 일정 스택을 사용할 수 있도록 해주세요.

오늘 날짜를 보는 경우에는 현재 시각을 기준으로 지난 일정과 앞으로 남은 일정을 구분해주세요.

과거 날짜를 선택했을 경우에는 해당 날짜의 전체 일정 및 수행 기록을 확인할 수 있어야 합니다. 과거 날짜의 모든 일정을 무조건 실패로 처리하지 말아주세요.

미래 날짜에서는 아직 발생하지 않은 일정이므로 지난 일정 스택을 표시하지 않습니다.

일간 화면의 시간대별 구조를 유지하면서 지난 일정 스택이 자연스럽게 포함되도록 디자인해주세요.

## 7. 지난 일정과 AI 비서 연동

삐꾸는 AI 개인 비서 서비스이므로 지난 일정을 다시 확인하는 것뿐만 아니라, 필요한 경우 AI의 도움을 받을 수 있어야 합니다.

지난 일정 카드의 더보기 메뉴에도 기존에 요청한 '삐꾸에게 부탁하기' 기능을 유지해주세요.

예를 들어 사용자가 완료하지 못한 운동을 선택하면 다음과 같은 요청을 할 수 있도록 해주세요.

- "오늘 운동을 못 했는데 다른 시간으로 옮겨줘."
- "내일 운동할 수 있는 시간을 추천해줘."
- "이 일정이 아직 필요한지 다시 확인해줘."
- "다음에는 이 루틴을 조금 더 일찍 배치해줘."

AI는 해당 일정의 정보와 기존 캘린더를 참고해 가능한 대안을 제안하고, 사용자가 수락·수정·거절할 수 있도록 해주세요.

실제로 수행하지 못했다고 확인된 작업에는 'AI로 다시 계획하기'를 제공할 수 있습니다.

다만 시간이 지났다는 사실만으로 사용자가 실패했다고 단정하거나 자동으로 AI 복구를 실행하지 마세요.

기존 일정 변경은 반드시 사용자 승인 이후에만 반영되도록 해주세요.

## 8. 카드 기능과 상태 일관성

지난 일정 스택을 펼쳤을 때 표시되는 카드도 현재 홈 화면의 카드 디자인과 기능을 동일하게 사용해주세요.

- 상태 버튼: 완료·미완료·참석 여부 등을 기록
- 더보기 버튼: 상세 정보, 수정, 삭제, AI에게 부탁하기
- 카드 본문 선택: 해당 일정의 상세 정보 확인

완료 상태를 변경하면 홈·일간 캘린더·루틴에 동일한 결과가 반영되도록 구성해주세요.

루틴의 특정 회차를 미완료로 기록하더라도 반복 루틴 자체를 삭제하거나 변경하지 않도록 해주세요.

## 9. 디자인 및 구현 시 주의사항

- 첨부 레퍼런스의 부드러운 라일락·블루 색감 유지
- 기존 둥근 화이트 카드와 타이포그래피 유지
- 카드가 겹치는 깊이감은 자연스럽게 표현
- 스택 내부의 제목이나 버튼이 잘리지 않도록 처리
- iPhone과 Android의 화면 너비에 맞게 반응형으로 구성
- 하단 내비게이션에 카드가 가려지지 않도록 처리
- 스택 펼침 상태에서 스크롤이 자연스럽게 작동하도록 구성
- 애니메이션 중 카드가 겹치거나 레이아웃이 튀지 않도록 구성
- 사용자가 선택한 필터에 맞는 일정만 스택 개수와 목록에 반영
- 지난 일정이 없는 경우에는 불필요한 빈 스택을 표시하지 않음
- 완료·미완료·확인 필요 상태를 시간 경과와 혼동하지 않음

## 10. 최종 목표

이번 수정의 목적은 새로운 화면을 많이 추가하는 것이 아니라, 기존 홈·오늘·일간 캘린더의 정보 구조와 사용자 경험을 개선하는 것입니다.

**현재와 미래의 일정은 전면에 보여주고, 지난 일정은 뒤쪽에 접힌 카드 레이어처럼 보관했다가 사용자가 원할 때 펼쳐 확인하는 경험**을 구현해주세요.

사용자는 현재 해야 할 일에 집중할 수 있으면서도 지난 일정의 수행 상태를 확인하고, 필요한 경우 AI에게 도움을 요청해 다시 계획할 수 있어야 합니다.

기존 디자인과 기능은 최대한 유지하고, 이번에는 지난 일정 스택의 접힌 상태·펼쳐진 상태·상태 변경·AI 연결 흐름을 중심으로 보완해주세요.

응, 정확히 이해했어. 지난 일정 스택을 화면 맨 아래에 배치하는 게 아니라, 첨부한 레퍼런스처럼 일정 목록의 위쪽에 배치하고, 지난 일정들이 뒤에 겹쳐 쌓여 있는 것처럼 표현하고 싶은 거지.

홈 화면과 일간 캘린더 모두 동일하게 적용하는 거야.

원하는 화면 구조 예시

오늘의 일정 요약

완료 2개 · 진행 중 1개 · 남은 일정 3개

지난 일정 3개

완료 2개 · 확인 필요 1개 · 눌러서 펼치기

현재 진행 중인 일정

데일리 미팅 준비 · 오전 11:00

앞으로 남은 일정

프로젝트 기획 점검 · 오후 1:00

즉, 위에는 지난 일정이 접혀 있고, 아래로 현재와 앞으로의 일정이 이어지는 구조야. 펼치면 그 자리에서 지난 일정 카드들이 나타나고, 다시 접으면 원래의 겹친 카드 형태로 돌아오는 거지.

## 기존 프롬프트에 추가할 수정 문구

지난 일정 스택 카드의 배치 위치를 수정해주세요.

앞서 지난 일정 스택을 남은 일정 아래쪽에 배치하도록 설명했지만, 제가 원하는 구조는 첨부한 레퍼런스 이미지처럼 **지난 일정들이 일정 목록의 위쪽에 겹쳐 쌓여 있고, 그 아래로 현재 진행 중인 일정과 앞으로 남은 일정이 이어지는 형태**입니다.

이 구조를 홈 화면과 일간 캘린더 화면 모두에 적용해주세요.

**1. 홈 화면**

- 상단 날짜·인사말·일정 요약은 유지해주세요.
- 일정 목록이 시작되는 위쪽에 지난 일정 스택을 배치해주세요.
- 지난 일정은 2\~3장의 카드가 뒤로 겹쳐진 듯한 레이어 형태로 표현해주세요.
- 그 아래로 현재 진행 중인 일정과 앞으로 남은 일정이 이어지도록 해주세요.
- 기존 AI 추천 카드는 유지하되 지난 일정 스택과 자연스럽게 어우러지도록 구성해주세요.

**2. 일간 캘린더**

- 날짜 선택 영역 아래의 일정 타임라인에서도 동일한 구조를 적용해주세요.
- 해당 날짜가 오늘이라면, 지난 일정 스택을 위쪽에 배치하고 현재·미래 일정이 그 아래로 이어지도록 해주세요.
- 시간순 흐름이 유지되도록 구성해주세요.
- 과거 또는 미래 날짜를 선택했을 때는 해당 날짜의 맥락에 맞게 표시해주세요.

**3. 펼치기·접기 동작**

- 기본 상태에서는 지난 일정들이 위쪽에 겹쳐진 카드처럼 보입니다.
- 사용자가 스택을 누르면 해당 위치에서 아래로 펼쳐져 지난 일정 목록이 나타납니다.
- 펼쳐진 일정은 최근 종료된 순서로 정렬해주세요.
- 다시 접으면 카드들이 위쪽의 레이어 형태로 돌아옵니다.
- 펼치거나 접을 때 아래쪽의 현재·미래 일정들이 자연스럽게 밀려나거나 복귀하도록 해주세요.

**4. 디자인**

- 첨부 이미지처럼 카드가 뒤에 쌓여 있는 깊이감을 살려주세요.
- 겹친 카드가 현재 일정이나 버튼을 가리지 않도록 해주세요.
- 기존 블루·라일락 색상과 둥근 카드 스타일을 유지해주세요.
- 하단 내비게이션과 화면 스크롤이 겹치지 않도록 해주세요.

핵심은 **지난 일정 스택이 화면 하단에 별도로 보관된 것이 아니라, 일정 목록의 시작 부분에 접혀 있고, 그 아래로 현재와 미래의 일정이 이어지는 구조**입니다.

지난 일정을 맨 아래에 배치하지 말아주세요. 홈과 일간 캘린더에서 동일한 UX를 사용하도록 수정해주세요.

이렇게 수정하면 네가 원하는 시간이 흘러갈수록 지난 일정은 위쪽 스택으로 접히고, 현재와 앞으로 해야 할 일정이 중심에 남는 UX가 만들어져.

## 현재 일정 뒤의 실제 카드 스택 의견 (style-reference, 2026-11-01)

현재 구현된 지난 일정 접기·펼치기 UI를 수정해주세요.

**제가 원했던 것은 '지난 일정 4개'라고 표시되는 별도 아코디언 카드가 아닙니다. 현재 시점의 일정 카드 뒤에 이전 일정 카드들이 실제로 겹쳐 쌓여 있는 레이어형 카드 스택(Stacked Cards UI)입니다.**

기존에 첨부했던 빨간색 표시 레퍼런스 이미지를 다시 참고해주세요. 그 이미지처럼 여러 카드가 뒤쪽에 겹쳐져 보이는 시각적인 깊이감을 원합니다.

### 1. 가장 중요한 디자인 변경

현재 구현:
- '지난 일정 4개'라는 별도 제목 카드
- 완료·미완료 개수 안내
- 펼치기·접기 텍스트와 화살표
- 제목 카드 위에 얇은 선을 추가해 레이어를 표현한 구조

원하는 구현:
- 별도의 '지난 일정' 제목 카드가 존재하지 않음
- 지난 일정 개수나 상태 요약 문구도 기본 화면에 표시하지 않음
- **현재 시점의 일정 카드가 가장 앞에 있고, 이미 지나간 일정 카드들이 그 뒤에 실제 카드 형태로 겹쳐 있음**
- 뒤쪽 카드들의 상단 가장자리, 둥근 모서리, 그림자 등이 조금씩 드러남
- 사용자는 드러난 레이어를 보고 이전 카드들이 쌓여 있다는 것을 직관적으로 이해함
- 뒤쪽의 노출된 카드 레이어를 누르면 실제 이전 일정 카드들이 펼쳐짐

**핵심은 '지난 일정을 접은 별도 컴포넌트'가 아니라, '현재 일정 카드와 과거 카드들이 하나의 카드 스택을 이루는 것'입니다.**

### 2. 접힌 상태의 시각적 구조

현재 진행 중인 일정, 또는 진행 중인 일정이 없다면 다음으로 다가오는 일정 카드를 전면 카드로 사용해주세요.

그 뒤로 이미 종료 시간이 지난 일정 카드들이 순서대로 겹쳐져 있도록 해주세요.

시각적 구성:
- 전면: 현재 또는 다음 일정 카드가 온전히 보임
- 바로 뒤: 가장 최근에 종료된 일정 카드의 상단 일부가 보임
- 그 뒤: 더 이전 일정 카드의 상단 일부가 보임
- 실제 지난 일정이 여러 개라면 시각적으로는 최대 2~3장 정도만 노출
- 별도 제목이나 개수 표시 없이 카드 레이어 자체로 의미를 전달

뒤쪽 카드들은 실제 카드 모양이어야 합니다. 단순한 얇은 장식선이나 가짜 테두리처럼 보이면 안 됩니다.

각 카드의 모서리, 그림자, 크기, 위치 차이를 활용해 실제 카드 여러 장이 뒤에 들어가 있는 듯한 깊이감을 만들어주세요.

예를 들어 카드마다 위쪽으로 약 6~10px씩 어긋나게 배치하고, 뒤쪽으로 갈수록 너비가 약간 줄어들도록 구성할 수 있습니다. 수치는 예시이므로 모바일 화면에서 가장 자연스럽게 보이는 비율을 선택해주세요.

뒤쪽 카드의 일부는 살짝 보이지만, 전면의 현재 일정 제목·시간·상태 버튼·더보기 버튼을 가리지 않아야 합니다.

### 3. 레이어 클릭 인터랙션

사용자가 전면 카드 뒤로 노출된 카드 레이어를 누르면 이전 일정들이 펼쳐지도록 해주세요.

접힌 상태:
- 현재 일정이 가장 앞에 있음
- 이전 일정들이 뒤에 겹쳐 있음
- 이전 일정 제목과 개수를 별도로 표시하지 않음
- 뒤쪽에 드러난 카드 영역을 터치해 펼칠 수 있음

펼쳐진 상태:
- 뒤에 겹쳐 있던 일정 카드들이 자연스럽게 분리되어 나타남
- 지난 일정은 가장 최근에 종료된 것부터 오래된 순서로 펼쳐짐
- 각 카드의 제목·시간·수행 상태·상태 변경 버튼·더보기 버튼을 정상적으로 사용할 수 있음
- 전면의 현재 일정 카드는 유지되며, 펼쳐진 지난 일정과 구분됨
- 사용자가 다시 접으면 이전 카드들이 전면 카드 뒤로 자연스럽게 겹쳐 들어감

펼치기 애니메이션은 겹쳐 있던 카드를 실제로 꺼내는 듯한 움직임이면 좋겠습니다.

단순히 숨겨져 있던 목록을 갑자기 표시하는 것이 아니라, 카드의 위치와 깊이가 변화하며 펼쳐지는 방식으로 구성해주세요.

전면 카드의 일반 터치는 해당 일정 상세 보기나 기존 상태 조작에 사용하고, 뒤쪽에 노출된 레이어 터치는 지난 일정 펼치기로 구분해주세요.

터치 영역이 지나치게 작지 않도록 하되, 두 동작이 충돌하지 않게 설계해주세요.

### 4. 시간에 따라 변화하는 카드 스택

현재 시간이 흐르면서 일정이 종료되면, 해당 일정 카드가 자연스럽게 과거 일정 스택으로 이동하는 구조를 원합니다.

예시:

오전 8시:
- 전면: 오전 8시 일정
- 뒤쪽: 그보다 이전에 종료된 일정들
- 아래: 앞으로 남은 일정들

오전 11시:
- 전면: 오전 11시 현재 일정
- 뒤쪽: 오전 8시·9시 등에 종료된 일정들
- 아래: 오후 1시·3시 등의 예정 일정

오후 3시:
- 전면: 오후 3시 현재 일정
- 뒤쪽: 그전에 종료된 일정들
- 아래: 이후 예정 일정들

즉, 시간이 지날수록 이전 일정들이 전면 카드 뒤에 차곡차곡 쌓이는 경험입니다.

단, 단순히 종료 시간이 지났다고 자동으로 완료나 미완료로 판정하지 마세요. 시간상 지난 일정인지와 사용자가 실제로 수행했는지는 별도의 상태입니다.

### 5. 홈 화면과 일간 캘린더에 동일하게 적용

이 구조는 홈 화면과 일간 캘린더 화면 모두에 적용해주세요.

홈 화면:
- 기존 상단 인사말, 오늘 일정 요약, AI 추천 영역 유지
- 일정 목록의 가장 위쪽에 현재 또는 다음 일정 카드를 배치
- 그 카드 뒤에 이전 일정 레이어를 쌓음
- 그 아래에 앞으로 남은 일정들이 이어짐

일간 캘린더:
- 현재 날짜의 시간대별 일정 화면에서도 동일한 스택 표현 사용
- 해당 날짜가 오늘이라면 현재 시점의 일정과 이전 일정을 구분
- 이전 일정은 전면 카드 뒤에 겹쳐 보이고, 이후 일정은 아래쪽 시간순 목록으로 표시
- 지난 일정을 펼쳤을 때는 일간 캘린더의 시간 순서를 이해할 수 있도록 카드의 시간 정보를 표시

과거 날짜나 미래 날짜를 선택한 경우에는 오늘 기준의 자동 스택을 무조건 적용하지 말고, 해당 날짜의 일정과 기록을 확인하기 적합한 구조로 처리해주세요.

### 6. 기존 기능 유지

지난 일정 스택을 펼쳤을 때 다음 기능은 그대로 사용할 수 있어야 합니다.

- 일정 상세 보기
- 완료·미완료·참석 여부 확인
- 완료 상태 변경 및 취소
- 수정·삭제
- 더보기 메뉴
- 삐꾸에게 부탁하기
- AI로 다시 계획하기

사용자가 지난 일정을 미완료로 기록한 경우에는 AI가 필요한지 확인한 후 새로운 시간을 제안할 수 있어야 합니다. 사용자가 승인하기 전에는 실제 일정을 변경하지 않습니다.

### 7. 기존 디자인 스타일 유지

기존 홈 화면의 전체적인 디자인은 변경하지 말아주세요.

- 연한 블루·라일락 배경
- 둥근 화이트 일정 카드
- 일정 유형별 색상 구분선
- 부드러운 그림자
- 현재 적용된 타이포그래피
- 상태 버튼과 더보기 버튼
- 중앙에 강조된 AI 비서 버튼
- 하단 내비게이션

새로운 별도 섹션이나 불필요한 제목을 추가하지 않고, 기존 일정 카드들을 활용해서 자연스러운 레이어 표현을 만들어주세요.

### 8. 반드시 피해야 할 구현

다음 방식으로 다시 구현하지 말아주세요.

- '지난 일정 4개'라는 제목을 가진 별도 카드
- '완료 2개 · 미완료 1개' 같은 상태 요약 헤더
- '지난 일정 보기', '펼치기' 등의 별도 버튼을 기본 화면에 추가
- 카드 위에 얇은 선만 여러 개 그려서 레이어처럼 표현
- 기존 일정 카드와 분리된 별도의 아코디언 섹션
- 뒤쪽 카드가 실제로 보이지 않는 단순한 목록 숨기기 기능
- 전면 카드의 버튼이나 제목을 레이어가 가리는 구조

**사용자가 별도의 설명을 읽지 않아도, 현재 일정 카드 뒤에 다른 카드들이 쌓여 있다는 것을 시각적으로 이해할 수 있어야 합니다.**

### 9. 이번 수정의 완료 기준

다음 네 가지를 확인할 수 있도록 수정해주세요.

1. 접힌 상태: 현재 일정 카드 뒤에 이전 일정 카드들이 실제로 겹쳐 보이는 화면
2. 펼쳐진 상태: 뒤쪽 카드들을 눌렀을 때 지난 일정들이 개별 카드로 자연스럽게 펼쳐지는 화면
3. 다시 접힌 상태: 펼쳐진 카드들이 다시 전면 카드 뒤로 들어가는 화면
4. 홈과 일간 캘린더: 동일한 카드 스택 UX가 적용된 화면

현재 구현된 아코디언형 '지난 일정 4개'는 제거하고, 기존 일정 카드를 재사용하는 실제 레이어형 카드 스택으로 변경해주세요.

**최종적으로는 현재 일정이 앞에 있고, 지나간 일정들이 그 뒤에 보관되어 있는 것처럼 느껴지며, 사용자가 뒤쪽 레이어를 누르면 과거 일정들을 다시 꺼내 볼 수 있는 경험을 원합니다.**

## 추가 메뉴와 작성 중 AI 요청 의견 (sketch-home, 2026-11-01)

현재 개별 일정의 더보기 메뉴에 구현된 '삐꾸에게 부탁하기' 기능을 추가(+) 메뉴와 일정 등록 화면에도 확장해주세요.

기존에 구현된 AI 강조 카드의 디자인이 마음에 듭니다. 새로운 디자인을 만들기보다는 해당 카드의 색상, 아이콘, 둥근 모서리, 여백과 타이포그래피를 재사용해주세요.

**1. 추가(+) 버튼의 첫 화면**

하단 추가(+) 버튼을 누르면 일정 등록 폼으로 바로 이동하지 않고, 먼저 다음 기능을 선택하는 바텀시트를 보여주세요.

상단에 AI 강조 카드:
- 삐꾸에게 부탁하기
- 설명: AI에게 말하면 일정과 계획을 만들어드려요.

아래에는 일반 추가 메뉴:
- 일정 추가
- 할 일 추가
- 루틴 추가

AI 기능은 기존 더보기 메뉴에 있는 것과 같은 연한 블루·라일락 배경과 반짝이는 아이콘을 사용해주세요.

**2. AI에게 새로운 일정 부탁하기**

'삐꾸에게 부탁하기'를 누르면 기존 AI 비서 대화 화면으로 이동하도록 해주세요.

이 경우에는 특정 일정이 선택되어 있지 않으므로 새로운 일정이나 작업을 생성하는 맥락으로 시작합니다.

예시 요청:
- "내일 오후 3시에 회의 잡아줘."
- "이번 주 남는 시간에 운동 일정 만들어줘."
- "오늘 할 일 정리해줘."
- "매일 아침 8시에 운동하는 루틴 등록해줘."

AI는 현재 일정과 사용자 선호를 참고하고, 필요한 정보가 부족할 때만 추가 질문하도록 해주세요.

새로운 일정이나 루틴을 제안하면 사용자가 내용을 확인하고 승인한 후에 저장하도록 해주세요.

**3. 일정 등록 폼에도 AI 기능 추가**

현재의 직접 입력 폼은 그대로 유지하되, 상단에 작은 'AI로 작성하기' 버튼이나 AI 강조 영역을 추가해주세요.

예를 들어 사용자가 일정 이름만 입력한 상태에서 AI에게 나머지 정보를 추천받거나, 자연어로 설명해 입력값을 채울 수 있으면 좋겠습니다.

AI가 생성한 입력값은 우선 작성 중인 초안으로 보여주고, 사용자가 내용을 확인한 후에만 실제 저장되도록 해주세요.

직접 입력한 기존 값은 사용자 동의 없이 덮어쓰지 않도록 해주세요.

**4. 기존 더보기 메뉴와 기능 구분**

기존 일정 카드의 더보기 메뉴에 구현된 '삐꾸에게 부탁하기'는 그대로 유지해주세요.

추가(+) 메뉴의 AI 기능은 새로운 일정을 생성하는 용도이고, 기존 일정의 더보기 메뉴는 선택한 일정에 관해 질문하거나 변경을 요청하는 용도입니다.

두 기능은 동일한 AI 비서 화면을 재사용하되, 진입 시 전달하는 일정 맥락만 다르게 처리해주세요.

**5. 디자인 및 기존 기능 유지**

- 기존 더보기 메뉴의 AI 강조 카드 디자인 재사용
- 추가 메뉴의 AI 기능을 가장 상단에 배치
- 기존 일정·할 일·루틴 입력 폼 유지
- 바텀시트 높이와 여백을 모바일 화면에 맞게 조정
- AI 버튼과 일반 등록 버튼의 시각적 위계 명확화
- 홈·캘린더·루틴·AI 비서의 기존 디자인 유지
- 새로고침 이후에도 기존 기능과 변경 사항 유지

이번 수정은 AI 화면을 새로 만드는 것이 아니라, 기존 AI 비서 기능에 접근할 수 있는 진입점을 확장하는 작업입니다.

핵심은 **사용자가 직접 입력할 수도 있고, AI에게 자연어로 부탁해서 일정·할 일·루틴을 만들 수도 있는 구조**입니다.

## 일간 캘린더 타임라인 의견 (sketch-day, 2026-11-01)

현재 일간 캘린더 화면의 전체적인 디자인 톤은 유지하되, 첨부한 첫 번째 레퍼런스 이미지의 시간 중심 레이아웃과 카드 디자인을 참고해 UX/UI를 개선해주세요.

현재 화면은 일정 카드가 단순히 세로로 나열된 형태에 가깝고, 왼쪽 시간축과 카드 내부의 시간 정보가 중복되며 시간 간격과 정렬도 어색합니다.

제가 원하는 것은 단순 일정 목록이 아니라 **시간의 흐름과 각 일정의 시작·종료 시각을 직관적으로 이해할 수 있는 타임라인형 일간 캘린더**입니다.

## 1. 전체 레이아웃 구조 개선

첨부한 첫 번째 이미지처럼 화면을 다음 구조로 구성해주세요.

상단:
- 현재 선택한 날짜와 월 표시
- 이전·다음 날짜 탐색
- 가로형 7일 날짜 선택 영역
- 월간 캘린더로 돌아가는 버튼

본문:
- 왼쪽: 일정의 시작·종료 시각을 나타내는 시간축
- 오른쪽: 해당 시간에 배치된 일정 카드
- 현재 진행 중인 일정은 컬러 카드로 강조
- 앞으로 남은 일정은 밝은 화이트·연회색 카드
- 지난 일정은 기존에 요청한 레이어형 카드 스택으로 표현

하단:
- 기존 홈 / 캘린더 / AI 비서 / 추가 / 루틴 내비게이션 유지

기존 블루·라일락 그라데이션 배경과 둥근 카드, 아이콘, 타이포그래피 스타일은 최대한 유지해주세요.

## 2. 시간축과 일정 카드의 관계 명확화

현재 왼쪽 시간축에는 오전 8:00, 오전 9:00, 오후 7:00 등이 표시되고 카드 내부에도 같은 시간이 반복되어 정보가 중복됩니다.

첫 번째 레퍼런스처럼 시작·종료 시간을 왼쪽 시간축에서 함께 보여주는 방식을 우선 적용해주세요.

예시:

왼쪽 시간축:
11:00
11:30

오른쪽 일정 카드:
데일리 미팅 준비
할 일 · 진행 중

또 다른 예시:

왼쪽 시간축:
13:00
14:00

오른쪽 일정 카드:
프로젝트 기획 점검
업무 · 예정

시간은 카드와 정확히 정렬되어야 하며, 시작 시간은 상대적으로 진하게, 종료 시간은 연한 회색으로 표시해주세요.

카드 내부에는 같은 시작·종료 시간을 반복해서 넣지 말고 일정 제목, 유형, 상태, 필요한 보조 정보만 표시해주세요.

단, 카드가 단독으로 표시되는 상황이나 상세 화면에서는 시작·종료 시간을 명확히 확인할 수 있도록 해주세요.

## 3. 시간 간격과 카드 배치 개선

현재는 실제 일정 간 시간 차이가 카드 사이 간격에 충분히 반영되지 않아 시간대별 일정이라는 느낌이 약합니다.

첫 번째 이미지처럼 왼쪽 시간축과 오른쪽 일정 카드가 하나의 행 또는 시간 블록으로 인식되도록 정렬해주세요.

- 시작·종료 시간이 카드의 위아래 위치와 자연스럽게 연결되도록 구성
- 일정 사이의 시간 간격을 시각적으로 구분
- 불필요하게 큰 여백은 줄이되 일정 간 공백이 있다는 사실은 인지할 수 있도록 표현
- 시간이 겹치는 일정은 무조건 한 줄로 나열하지 않고 겹침 여부를 알 수 있도록 표시
- 짧은 일정도 제목과 주요 기능을 읽을 수 있는 최소 카드 높이 확보
- 긴 일정은 필요한 정보를 표시할 수 있도록 카드 높이를 유연하게 조정

실제 일정의 길이를 완전히 동일한 비율로 표현하는 엄격한 시간 격자보다는 모바일 화면에서 읽기 쉬운 일정 블록형 타임라인을 우선해주세요.

다만 시간순 정렬과 시작·종료 시각의 정확성은 반드시 유지해주세요.

## 4. 현재 진행 중인 일정 강조

첫 번째 레퍼런스에서 가장 마음에 드는 요소는 현재 진행 중인 일정이 색상으로 채워져 있어서 한눈에 파악된다는 점입니다.

삐꾸에도 이 방식을 적용해주세요.

현재 진행 중인 일정:
- 블루·퍼플 또는 민트 계열의 채워진 컬러 카드
- 제목과 핵심 정보의 높은 가독성
- 필요하다면 '진행 중' 상태를 작은 문구로 표시
- 현재 일정이 여러 개라면 실제 겹치는 일정을 모두 확인할 수 있도록 구성

앞으로 남은 일정:
- 화이트 또는 매우 밝은 회색 카드
- 현재 일정과 구분되는 차분한 색상
- 일정 유형과 상태를 쉽게 확인할 수 있도록 표현

완료된 일정:
- 완료 상태가 명확하게 드러나되 과도한 색상 강조는 피해주세요.

현재 진행 중 여부는 시작·종료 시간에 따른 표시이고, 사용자가 실제 완료했는지 여부와는 별개입니다. 시간이 지났다는 이유로 자동 완료 처리하지 말아주세요.

## 5. 지난 일정 레이어 스택 유지 및 통합

기존에 요청했던 Stacked Cards UI를 이번 일간 타임라인에도 적용해주세요.

별도의 '지난 일정 4개'라는 제목 카드나 펼치기 버튼을 만들지 말아주세요.

현재 진행 중이거나 다음에 예정된 일정 카드를 전면에 보여주고, 이미 종료된 일정 카드들이 그 뒤쪽·위쪽에 실제로 겹쳐 있는 형태를 원합니다.

- 지난 카드의 둥근 모서리와 상단 일부가 자연스럽게 보이도록 구성
- 사용자에게 이전 카드들이 뒤에 쌓여 있다는 시각적 단서 제공
- 노출된 레이어를 누르면 지난 일정 카드들이 자연스럽게 펼쳐짐
- 펼친 상태에서는 가장 최근에 종료된 일정부터 이전 일정 순으로 표시
- 다시 접으면 현재 일정 카드 뒤로 카드들이 들어가는 애니메이션 적용

전면 일정 카드의 상세 보기·상태 버튼·더보기와 지난 일정 레이어의 펼치기 동작이 충돌하지 않도록 해주세요.

지난 일정이 없으면 스택을 표시하지 않고, 현재 진행 중인 일정이 없으면 다음으로 다가오는 일정을 기준으로 구성해주세요.

지난 일정을 펼쳤을 때도 각각의 시작·종료 시간을 정확히 확인할 수 있어야 합니다.

## 6. 일정 카드 내부 정보 최적화

현재 카드에는 시간, 소요시간, 유형, 상태, 완료 버튼, 더보기 버튼이 모두 들어가 있어 다소 복잡해 보입니다.

일간 타임라인에서는 다음 정보에 우선순위를 두어주세요.

1. 일정 제목
2. 일정 유형 또는 필요한 보조 정보
3. 수행 상태
4. 빠른 상태 변경 버튼
5. 더보기 버튼

시작·종료 시각은 기본적으로 왼쪽 시간축에서 보여주므로 카드 내부에 중복 표시하지 않습니다.

다만 다음과 같은 정보는 필요에 따라 카드 내부에 표시할 수 있습니다.
- 장소
- 참석자
- 고정·유동 여부
- AI 제안 대기 상태

모든 카드에 모든 보조 정보를 넣을 필요는 없습니다.

카드가 길어지거나 복잡해지지 않도록 핵심 정보만 보여주고, 자세한 내용은 카드 선택 시 상세 화면에서 확인하도록 구성해주세요.

## 7. 완료·참석 확인 및 더보기 기능 유지

기존에 구현한 상태 버튼과 더보기 메뉴 기능을 유지해주세요.

- 할 일·루틴: 완료 여부 기록
- 약속·회의: 참석 여부 확인
- 더보기: 상세 정보, 수정, 삭제, 완료 상태 변경, 삐꾸에게 부탁하기

## 8. AI 비서 기능과 연결

삐꾸는 일반 캘린더 앱이 아닌 AI 개인 비서 서비스입니다.

일정 카드의 더보기 메뉴에 구현한 '삐꾸에게 부탁하기' 기능을 유지해주세요.

선택한 일정의 정보가 AI 대화 맥락에 전달되어 사용자가 해당 일정에 대해 질문하거나 변경을 요청할 수 있어야 합니다.

예시:
- "이 일정 30분 늦춰줘."
- "다음 회의 준비할 시간 추천해줘."
- "이 일정이 다른 일정이랑 겹치는지 확인해줘."
- "오늘 못 했는데 다른 시간으로 다시 계획해줘."

AI는 기존 일정과 사용자 선호, 고정 일정 등의 제약을 고려해 대안을 제안해야 합니다.

일정 변경은 사용자가 수락한 후에만 반영하고, 다른 사람이 참여하는 공동 약속 변경은 기존 연락 승인 흐름을 유지해주세요.
