# 시계는 워치 — PIKKU 제출 체크리스트

기준: 사용자가 제공한 「(최종) 코디세이 AI 해커톤 2026 참가자 가이드 (1).pdf」(14쪽, 문서 표기 2026-10-13). 제출 요건은 3~4쪽, 심사·제한은 5~7쪽을 확인했다. 아래는 제출 준비 기록이며 실제 Google Drive 업로드 완료를 뜻하지 않는다. 가이드 원본·개인정보 서류는 저장소에 올리지 않는다.

## 필수 제출물

**2026년 11월 1일 13:00 한국시간까지 팀별로 공유받은 Google Drive에 업로드한다.** 참가 신청 이메일과 최종 결과물 제출 경로를 혼동하지 않는다. Drive 업로드 시간이 기준이며 심사는 제출한 최종 커밋 해시를 사용한다.

| 제출물 | 가이드 요건 | 현재 준비 상태 |
|---|---|---|
| 발표자료 | PDF, 표지 제외 10페이지 이내, 아래 필수 7개 항목 | 이 작업에서 생성·분량 검수하지 않음. 팀 최종 파일 필요 |
| 시연 영상 | MP4, 2분 이내, 실제 앱 입력→결과 화면 녹화, 1080p 이상 권장 | 이 작업에서 녹화·파일 검수하지 않음. 팀 최종 영상 필요 |
| 소스 코드 | Public GitHub, 전체 소스·README 설치/환경설정/실행 안내 | 공개 저장소 확인, README 및 환경 예시 보완 |
| 소스 제출용 텍스트 | `시계는 워치_소스코드.txt`에 GitHub URL과 최종 전체 커밋 해시 | 문서 병합 완료 후 저장소 밖 제출 폴더에 생성. Drive 업로드는 별도 |

저장소: https://github.com/codyssey-hackerton/codyssey-hackathon-bbikku

웹앱: https://pikku-bbikku-web-preview.vercel.app/

## 발표자료 필수 7항목

| 항목 | 준비할 내용·재사용 가능한 근거 |
|---|---|
| 문제 정의 및 목표 사용자 | 일정 기록 이후 준비·이동·변경 판단의 부담. [README](../README.md), [PRD](PRD.md) |
| 해결 방안 및 주요 기능 | 개인 맥락→추천→검증→승인→일정 반영. 기능과 미검증 범위를 구분 |
| 활용 AI 기술 및 직접 개발 범위 | 단일 계획 LLM·Tool Calling·LangGraph, 직접 개발한 시간/충돌/승인/멱등 경계. 모델 학습으로 표현하지 않음 |
| 개발 환경 및 기술 스택 | Expo/React Native/TypeScript/Fastify/PostgreSQL/pg-boss, Vercel·VM |
| 팀원별 역할 분담 | [팀 계획](TEAM_PLAN.md)을 실제 기여에 맞춰 팀 최종 확인 |
| 외부 자원 활용 내역 | [외부 자원 표](EXTERNAL_RESOURCES.md)의 **구분 / 명칭 / 용도 / 라이선스** 형식. 실제 사용 내역을 발표자료에도 포함 |
| 기대 효과 및 확장 가능성 | 계획 조정 부담 감소는 기대 효과. 정량 효과 미측정. 실기기/알림 검증·연동 신뢰성 개선 등 후속 방향 |

외부 자원·사전 보유 코드 미기재의 감점 및 실격 규정이 있으므로, 코드 공개만으로 해당 표를 생략하지 않는다. 사전 보유 코드가 없다는 팀 확인을 받기 전에는 ‘해당 없음’으로 기재하지 않는다. Aria 등 디자인 참고와 팀원의 추가 도구·이미지·데이터도 확인한다.

## 2분 영상 구성 제안

아래 시간 배분은 팀 제안이며 가이드의 필수 대본이 아니다. 디자인 목업만 보여주는 영상이나 화면 없는 설명은 인정되지 않는다.

| 구간 | 실제 화면과 확인할 결과 |
|---|---|
| 0~15초 | PIKKU 서비스·문제 한 문장, 로그인된 홈 |
| 15~35초 | 선호와 일정/할 일 입력. 실제 저장된 상태 표시 |
| 35~80초 | PIKKU에 일정 조정 요청 → 조회/추천 → 구체적 변경 카드. 모델 응답 시간은 실제로 녹화 |
| 80~105초 | 승인 전 원래 일정 → 수락 → 캘린더의 변경 결과 |
| 105~120초 | 완료/참석 기록이나 연결된 Calendar 등 검증된 기능 한 개와 한계 요약 |

이미 준비된 계정·권한으로 먼저 리허설한다. 연락을 시연하면 수신자 동의를 받고 실제 연락과 모의 결과를 구분한다. 계정 이메일·전화번호·API 키·토큰은 영상에 노출하지 않는다. 성능을 과장하지 않도록 편집·대기 생략은 명확히 표시한다.

## 업로드 직전

- [ ] PDF 표지 제외 10페이지 이내, 필수 7항목과 외부 자원 4열 표 포함.
- [ ] MP4 재생·길이 120초 이하·판독 가능한 실제 동작 확인.
- [ ] 사전 보유 코드, 디자인/캐릭터 권리, 추가 외부 자원 및 팀원 기여 확인.
- [ ] Public 저장소를 로그아웃 상태에서도 열 수 있고 최종 커밋의 README가 존재.
- [ ] 문서/코드 최종 병합 후 전체 해시를 텍스트에 기재. 텍스트 안 해시와 원격 커밋 일치.
- [ ] 세 제출물(PDF·MP4·소스 텍스트)을 지정 Drive에 업로드하고 업로드 시각·열람 가능 여부 확인.
- [ ] 심사 종료까지 저장소를 삭제하거나 비공개로 바꾸지 않음.

`시계는 워치_소스코드.txt`는 최종 커밋 이후 생성하므로 자체 커밋 해시를 같은 커밋 안에 넣는 순환을 만들지 않는다. 최종 제출 이후 개발을 계속하더라도 제출 해시를 임의로 바꾸거나 이후 개발을 심사 대상에 포함했다고 주장하지 않는다.

## 2차 발표 시 유의사항

가이드 5~7쪽 기준 11월 2일 대면심사는 발표 7분(라이브 시연 3분 이상·설명 4분 이내), Q&A 5분이다. 자료는 1차 제출 범위 안에서 문구·순서·가독성만 보완하고 새로운 기능·결과물을 추가하지 않는다. 수정본은 해당일 12:00까지 제출하며, 최종 운영 안내가 별도로 오면 팀에서 대조한다.
